# Plan for #178

## Implementation

### Steps

Decisions: generator is **MkDocs Material** (nav, search and `mkdocs build --strict` link checking come built in; Hugo and Jekyll need more custom work for the same result). Pages live in `docs/site/`; `mkdocs.yml` is new at the repo root with `docs_dir: docs/site`. `docs/proposal.md`, `docs/layout.md` and `docs/TODO.md` stay outside the site and user pages link to the proposal by absolute GitHub URL (strict mode rejects links leaving `docs_dir`). The Gate 2 runbook is copied-by-move into the site (step 4).

1. **Config key source of truth (new, `internal/config/keys.go`).** Add `func Keys() []string` returning every documented dotted key: the top-level keys, `intervals.*`, `intake.mode|label`, `merge.protected_paths`, `stale.*`, `redact.gitleaks.*`, `sidecars.<name>.repo|ref`, and the override keys (`every`, `max_open`, `group_size`, `autoclose`, `route`, `model`, `timeout`, `sidecar`, `after`, `plan_section`, `tests`, `max_test_fixes`, `max_review_rounds`, `reviewers`, `diff_warn_lines`, `diff_max_lines`, `agent`). Derive from the `yaml:` tags of `resolvedYAML` and `roleYAML` in `internal/config/render.go` by reflection, and add the input-only keys (`merge.protected_paths`, `overrides`) from the list parsed in `internal/config/raw.go`. Add `keys_test.go` that fails if a key parsed in `raw.go` is missing from `Keys()` (so the list cannot lag the loader). Reason: the docs check needs one list that tracks the code.
2. **CLI command source (new, `internal/cli/commands.go`).** Add `func CommandPaths() []string` that walks `NewRoot(&App{})` and returns every command path (`ard serve`, `ard config check`, `ard labels sync`, `ard rebuild-state`, `ard init`, `ard version`) with each command's flag names (`--dry-run`, `--loops`, ...). No change to `NewRoot`.
3. **Docs drift test (new package `internal/docscheck`, `docscheck_test.go`).** Read `docs/site/**/*.md` from the repo root (found by walking up to `go.mod`). Rules: (a) every inline or fenced `ard <words>` command that starts a line or an inline code span must resolve to a path in `cli.CommandPaths()`, and every `--flag` on that line must be a flag of that command or a global flag; (b) the page `docs/site/configuration.md` must list every `config.Keys()` entry as a backticked key in a table (undocumented key fails), and every backticked key in that table must be in `Keys()` (stale key fails). Lines can opt out with `<!-- docscheck:ignore -->` on the previous line. Pure Go, runs in `go test ./...`, so `make test` covers it.
4. **Site scaffolding.** New `mkdocs.yml` (Material theme, `site_url: https://albertcbrown.github.io/ard/`, `docs_dir: docs/site`, `strict: true`, search plugin, nav listing the pages below). New `docs/site/requirements.txt` pinning `mkdocs` and `mkdocs-material` versions. Add `site/` to `.gitignore` (edit existing file). Move `docs/runbooks/gate-2.md` to `docs/site/operations/gate-2-runbook.md` with `git mv` and update any references (`grep -rn "runbooks/gate-2"`, including `docs/layout.md`, README and `docs/proposal.md`).

### Test plan

Command: `make test` (runs `go test ./...`); also `make lint`; `make docs-check` when mkdocs is installed.

- `TestKeysCoverRawParser` (`internal/config/keys_test.go`): every key the parser in `raw.go` accepts appears in `Keys()`. Failure case: a key added to the parser alone fails it.
- `TestCommandPaths` (`internal/cli/commands_test.go`): expected paths include `ard config check`, `ard labels sync`, `ard serve` with `--loops`, `ard init`.
- `TestDocsCommandsExist` (`internal/docscheck`): passes on the real docs. Cases using a temp docs dir: `ard bogus` fails; `ard serve --nope` fails; `ard serve --dry-run` passes; line preceded by the ignore comment passes.
- `TestDocsConfigKeysMatch`: undocumented key in a fixture table fails with the key's name; stale documented key fails; the real `configuration.md` passes.
- Manual (human, listed in the issue's done-when): follow Getting started on a scratch repo to a first triaged issue and note it in the PR; verify the live site after the maintainer adds the workflow.
- Edge cases: commands in fenced blocks with `$ ` prompts or `\` continuations; `ard` appearing in prose (only code spans and fenced blocks are checked).

### Risk

Low. No runtime code changes: two small read-only exported helpers in `internal/config` and `internal/cli`, a test package, docs and a Makefile target. None of `merge.protected_paths` is touched by the agent PR (no `.github/`, `.ard/config.yaml`, role dirs, Dockerfile, deploy/). The `Keys()` list is a new public (internal) interface that must track the loader; the step 1 test guards that. The deploy workflow, the Pages setting and the CI steps for the site build are a human follow-up (step 8). Documentation accuracy is the main residual risk and needs the manual scratch-repo run.
