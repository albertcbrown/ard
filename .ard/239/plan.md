# Plan for #239

## Implementation

### Steps
1. `internal/config/types.go`, `raw.go`, `defaults.go`, `keys.go`, `render.go` (+ new `internal/config/limits.go`): add a top-level `limits:` block. New `type Limits struct { StopWorkersPct, StopAllPct int; WeeklyStopWorkersPctByDay []int; WeeklyStopAllPct int }` as `Resolved.Limits`; a `rawLimits` parser (new, same style as `rawIntervals.parse`, registered as `case "limits"` in the key switch in `raw.go`). Defaults: `stop_workers_pct: 75`, `stop_all_pct: 90`, `weekly_stop_workers_pct_by_day: [20,35,50,60,70,80,85]`, `weekly_stop_all_pct: 90`. Validation (errors name the key like other config errors): percents are ints in 1..100; `stop_workers_pct <= stop_all_pct`; the list has exactly 7 ints in 1..100, non-decreasing, each `<= weekly_stop_all_pct`. Add the dotted keys to `Keys()` and make `render.go` print them (TestKeysCoverRenderedConfig requires both; also update the user docs key table it checks).
2. `internal/limits/policy.go` (new): `type Policy struct{ StopWorkersPct, StopAllPct, WeeklyStopAllPct int; WeeklyByDay [7]int }`, `func PolicyFrom(config.Limits) Policy` (or a plain constructor, to avoid an import cycle if config imports limits), `type Gate int` (`Allow`, `Hold`/no-workers, `Deny`) and `func (b *Book) Gate(p Policy, tier Tier, family string) (Verdict, reason string)` where Tier is `TierWorker` (workers, triage, agent scanners) or `TierReviewer`. Reads `b.Readings()` windows `five_hour` and `seven_day`. Utilization is "as the stream reports it": existing tests show both fractions (0.42) and percents (85); normalise (value <= 1 means fraction) in one helper and test both. Day of window: `start = resets_at - 7d`, `day = clamp(floor((now-start)/24h)+1, 1, 7)`; no `resets_at` (zero) uses day 7 (list[6]). Ignore a reading whose `resets_at` is past (the window rolled over; stale) for the 5h and weekly windows. Rules: 5h or weekly utilization `>= stop_all` → Deny all agent tiers; worker tier also Deny at `>= stop_workers_pct` (5h) or `>= list[day-1]` (weekly); a reviewer is held only by the stop-all values. 5h `>= stop_workers_pct` also sets `Serial` (one agent job at a time); weekly never sets it. The existing `Until(family)` book (reactive pauses, Opus-only) stays the separate per-family check, so an Opus limit blocks only Opus roles.
3. `internal/pool/candidate.go`, `pool.go`: add `Candidate.Agent bool` (a `agent: claude` job that counts toward the one-job rule) and `Candidate.Serial bool` (must not start while another Agent job is held or granted earlier in this batch). Add `Options.Annotate func(Candidate) Candidate` (new, nil = no-op) applied to every offered candidate and every `Held` entry, so the five loop call sites that build `pool.Candidate` need no edit. Add verdict `DeniedSerial` (append to the verdict list and `verdictNames`). In `Offer`'s ranked walk, before granting, deny a `Serial` candidate when `agentHeld + agentGrantedThisBatch > 0`, taking no slot and reserving no demand (like `DeniedLimited`, via `noteRefusalLocked` if its signature allows). Held slots are never affected. `Serial` is evaluated per Offer, so it must be recomputed by Annotate each tick from the current reading.
4. `internal/servecmd/reaping.go` (`limitedFor`, `limitsBook`) and `serve.go` (pool construction; `adopt.go` `adoptPool`): extend `limitedFor` so for a role with `Agent == "claude"` (resolved role/global agent; deterministic scanners with `ScanPath` and the merger stay exempt) it also calls `Book.Gate` and returns a blocked-until time (the window's `resets_at`, or now+poll interval when unknown) on Deny. Add `w.annotate(c)` setting `Agent` and `Serial` from the same gate, and pass it as `Options.Annotate` in both pool constructions. The issue mentions a "limits loop with `Claims() == false`": no such loop exists today (14 loops, `rebuild_test.go:196`). Do not add one unless needed; if a loop is added, it must return `Claims() == false` and the count in `rebuild_test.go` and the loop-order list change.
5. `docs/proposal.md`: Executors and the Reaper paragraph (the "Nothing is gated on the readings yet (#63)" sentence) and the Configuration section's `limits:` block: describe the 5h thresholds, paced weekly list and day calculation, the 5h-only one-job rule, reviewers until stop-all, Opus pausing only Opus roles, and that deterministic scanners and the merger are unaffected. Also update the `Reading` doc comment in `internal/limits/readings.go` ("Nothing gates on it yet").
