2. `internal/executor/kube/roleimage.go` (new): the role image builder.
   - `type RoleImages struct { Namespace, BuilderImage, Repository, PushSecret string; BuilderUID int64; AgentBase string (default "ghcr.io/albertcbrown/ard/agent:latest"); Budget time.Duration (default 15m); Registry string (default "https://ghcr.io"); MaxContext int64 (default 512 KiB) }`; a new `Options.RoleImages *RoleImages` (nil = images off, keep `kube.dockerfile_ignored`). `New` validates fields and `executor.CheckImageRef(BuilderImage)`.
   - `func (e *Executor) roleImage(ctx, j executor.Job) (ref string, err error)`:
     a. Read the role directory from the controller clone at the pinned SHA, never the worktree: `git ls-tree -r -z <RoleSource.SHA> -- <RoleSource.Path>` in `j.RepoDir` for mode, blob id and relative path (use the existing git runner interface from `workspace.Options.Git` / `local.ExecGit`; read how `internal/executor/workspace` calls it). Reject symlinks (mode 120000) and submodules, and a missing `Dockerfile` in the listing.
     b. Tag `h-<first 32 hex of sha256 over sorted "mode path blobid\n" lines>`; include the base build-arg value in the hash input so changing `AgentBase` rebuilds. Repository `<Repository>/<stage-type>-<role>` where type is `scanners|triage|workers|reviewers` from `RoleSource.Path` (`.ard/<type>/<name>`); validate both segments against `^[a-z0-9][a-z0-9-]*$`.
     c. Registry check: anonymous pull token (`GET <Registry>/token?service=ghcr.io&scope=repository:<repo>:pull`), then `HEAD /v2/<repo>/manifests/<tag>` with OCI and Docker manifest Accept headers; 200 returns `Docker-Content-Digest`, so the ref is `<repo>@<digest>`. 401, 403 and 404 mean "not built yet" (a package that is still private looks the same), so go on to build. Other errors/5xx/timeouts fail the job as `registry check`. Use `Options.HTTP`.
     d. Single-flight per tag (`map[string]*call` under `e.mu`) so concurrent jobs for one role share one build and one result.
     e. Build: export the context with `git archive --format=tar <sha>:<path>` (cap at `MaxContext`; a larger context fails clearly), create a Secret in the build namespace holding it, then the builder pod copying the exact #448 admission shape (read `deploy/charts/ard-serve/templates/build-namespace.yaml` for volumes, uid, seccomp/AppArmor Unconfined, resources; do not edit it). Command: `buildctl-daemonless.sh build --frontend dockerfile.v0 --local context=/ctx --local dockerfile=/ctx --opt build-arg:AGENT_IMAGE=<AgentBase> --output type=image,name=<repo>:<tag>,push=true --metadata-file /dev/termination-log` (adapt flags to what the pinned BuildKit supports; the digest comes from `containerimage.digest`). Pod name `ard-build-<tag12>`, labels `app.kubernetes.io/instance`, `ard.dev/role-image`, restart never, `activeDeadlineSeconds` = Budget. Set the Secret's ownerReference to the pod after creation like `buildSecret` in `pod.go`.
     f. Wait by polling `GetPod` every `Options.Poll` until Succeeded/Failed/deadline. Failure causes, each a typed error wrapping `executor.ErrInvalidJob`-independent sentinel `ErrRoleImageBuild`: `build failed (exit N): <last 20 log lines, redacted with internal/redact>`, `build timed out after <Budget>`, `builder pod not scheduled/admission denied: <create error>`, `no digest reported`. Always delete pod and Secret on exit with `context.WithoutCancel`.
     g. Return `<repo>@sha256:...`; reject any digest that is not `sha256:` + 64 hex.

### Network inputs

### Test plan
Test command: `make lint test` (`go test ./internal/executor/... ./internal/servecmd/...` for a quick loop).
- `internal/executor/kube/roleimage_test.go` (new), with the fake client, a fake git runner and an `httptest` registry:
  - TagStable: same tree gives same tag; changing a file, a mode, the Dockerfile or `AgentBase` changes it; file order does not.
  - CachedSkipsBuild: registry HEAD returns 200 plus digest, so no pod or Secret is created and `h.Image` is `<repo>@<digest>`.
  - BuildSuccess: HEAD 404, builder pod created in the build namespace with the exact pinned shape (image, uid, SA, Secret mounts, `activeDeadlineSeconds`, no `imagePullSecrets`), scripted Succeeded with a digest, pod and Secret deleted, ref returned.
  - PrivatePackage401: token or HEAD returns 401, so it builds.
  - RegistryDown: HEAD 500 fails with a `registry check` cause and builds nothing.
  - BuildFailure: Failed with exit code 1 and logs, so the error names the exit code and log tail, secrets in logs redacted.
  - BuildTimeout: pod stays Running past a short `Budget`, so the error says timed out and the pod is deleted.
  - AdmissionDenied: `CreatePod` returns an error, so the error says the builder was refused and the Secret is removed.
  - BadDigest: termination message without a valid sha256 digest fails.
  - SingleFlight: two concurrent Prepare calls for one role create one builder pod.
  - ContextFromSHA: the archive and the tag come from `RoleSource.SHA`, not from `j.RoleDir` or the worktree (create a differing file in `RoleDir`; it must not appear).
  - Rejects: symlink in the role dir, missing Dockerfile, oversize context, bad role path segments.
- `kube_test.go`: Prepare with a Dockerfile and `RoleImages == nil` still logs `kube.dockerfile_ignored` and uses `AgentImage`; with it set, the agent container image is the digest ref and `PodImage` is still used for the init/result containers (`pod_test.go`); a build failure leaves no live job and no worktree.
- `internal/servecmd/k8s_test.go`: env/flags map to `RoleImages`; build namespace unset keeps images off; partial settings or a non-digest builder image give an error.
- `internal/executor/local`: `docker build` args include `--build-arg AGENT_IMAGE=` only when set.
- Edge: Dockerfile role with no network access to ghcr, push credential Secret missing (builder pod stays Pending: covered by the build budget).

### Risk
Medium. New outward network use (registry check) and a new pod type holding the push credential; the controller token can already create these (#448 residual risk) and this adds the code path. No migrations, no concurrency beyond one single-flight map, no change to `deploy/` expected (builder RBAC already exists; if the worker finds the Role needs more, that is under `merge.protected_paths` and needs a human). `docs/proposal.md` and Go code are not protected paths. Recorded residual risk: `:latest` base hides base changes under an unchanged tag.
