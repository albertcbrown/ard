# Plan for #435

## Implementation

### Steps

1. `internal/state/migrations/0009_pending_pr.sql` (new): `ALTER TABLE jobs ADD COLUMN pending_pr TEXT` (nullable, no default). Additive, so existing job rows read as NULL and keep today's behaviour. Follow the numbering and style of `0008_pr_watch.sql`.
2. `internal/state/jobs.go`: add `PendingPR json.RawMessage` to `Job` and to `jobCols`/scan code. Add `SetPendingPR(ctx, id string, p PendingPR) error` (uses `updateRunning`, like `SetPR`) and `LatestPendingPR(ctx, issue int, role string) (Job, bool, error)`, which returns the newest ended worker job for the issue and role. The newest job is the only candidate: if a later job exists, it superseded the record. New type `state.PendingPR{Branch, Head, Title, Body string; Tests string}` (JSON). Title and body are the rendered PR text, already redacted and sanitised by `Body`.
3. `internal/closeout/closeout.go`: add `CausePRCreateFailed CauseKind = "pr_create_failed"`, documented as non-transient, `Retry` false. Check that comment rendering and any switch over cause kinds (grep `CausePushTransient` users: `closeout.go:644`, `internal/worker/run.go:645`) handle the new kind. It must go through `failedPlan`, so the job ends `executor:failed` with one comment.
4. `internal/github/errors.go`: no change. `github.IsTransient` already classifies 5xx, rate limits and timeouts, and the push retry from #357 has landed (`CausePushTransient`, gitx classifier). Reuse `IsTransient` for CreatePR, so no new classifier is needed.
5. `internal/worker/pr.go` (or new `internal/worker/prretry.go`): add `createWithRetry(ctx, in github.NewPR) (github.PullRequest, error)`. Up to 4 attempts with backoff 2s, 5s, 15s, taking the sleep from a new `Deps.Sleep func(ctx, time.Duration)` field (nil means a real timer; tests pass a no-op). Retry only when `github.IsTransient(err)`; stop at once on context cancellation. Before each retry call `Reader.ListPRs` for the head, in case the earlier create actually succeeded, and use that PR if found. Under dry-run (`l.dry()`/`Effects.DryRun()`), log `worker.pr_retry` only and do not sleep or retry.
6. `internal/worker/run.go` `openPR` (around lines 840-880): use `createWithRetry` in place of the direct `Effects.CreatePR`. When the create still fails and `jb.pushed` is true, call `Store.SetPendingPR` with the branch, `jb.head`, title, body and tests result, then `jb.finish(..., jb.cause(closeout.CausePRCreateFailed, fmt.Sprintf("pushed branch %s at %s; only the pull request is missing", jb.branch, short(jb.head)), false))`. Other failures (`title`, `list`, `update`, `record`) keep the `no_process` cause. A failure with no push this job (existing branch, no new code) keeps today's behaviour. Log `worker.pr_failed step=create` as now.
7. `internal/worker/run.go` `exec`/`claim` (before `agentStep`, around line 210): new `jb.reopenPR(ctx) bool`. When `exists` is true and `Store.LatestPendingPR` returns a record for this issue and role, fetch the branch tip (`Git.LsRemote` on `refs/heads/<branch>`). If the tip equals `rec.Head` and `ListPRs` finds no open PR for the branch, call `createWithRetry` with the recorded title and body, call `SetPR`, `finish` with `closeout.WorkerResult{Tests: <recorded>, Pushed: true, PR, PRURL}` and `closeout.Cause{}`, and return true so no agent step or test run happens. If the tip differs, or a PR already exists, or the lookup fails, return false and fall through to the full run as today. A create failure here ends again with `pr_create_failed` and a refreshed record. `StartAttempt` still runs first so the job is a normal started job. Check the result-to-role-file path: close-out normally reads a role file from the agent step (`jb.final`). Confirm in `finish`/`Finisher.FinishWith` that a `step{}` with `Worker` set can produce `done` without a role file. If it cannot, add a small `closeout` path for a synthetic done result (summary taken from the recorded body) and keep it covered by a test.
8. `internal/roles/workers/engineer/prompt.txt`: add one short rule: when the branch already holds a complete implementation of the plan and no PR exists, answer `done` with the original summary, not `needs-human`. Do not touch `.ard/workers/engineer/prompt.txt` (protected path); see Risk.
9. `docs/proposal.md`: update the worker loop PR step: the `pr_create_failed` cause, the retry budget, the agent-free re-open and its fallback, dry-run behaviour, and the new job column. Run `make lint test`; the repo has a docs check (`internal/docscheck`), so keep it consistent.

### Test plan
Test command: `make lint test`. All tests use the GitHub fake (`internal/github/fake`) and the harness in `internal/worker/harness_test.go`; no network. `FailNext` is one-shot per call, so call it twice for the "fails twice" case, or add a `FailTimes(method, err, n)` helper to the fake, marked new.
- `TestCreatePRRetriesThenOpens` (`internal/worker/loop_test.go`): `FailNext("CreatePR", 5xx HTTPError)` twice, then success. Expected: one PR is opened, one agent step ran (`len(h.ex.jobs)==1`), no `executor:failed` label, outcome done.
- `TestCreatePRAlwaysFails`: the fake always fails with a 5xx. Expected: the job ends `executor:failed` with cause kind `pr_create_failed`, `Retry` false, one comment whose detail names the branch and short head; `jobs.pending_pr` is recorded.
- `TestCreatePRNonTransientNotRetried`: a 422 error causes one `CreatePR` call, then `pr_create_failed` (pushed) as in the failure case.
- `TestReopenPRWithoutAgent`: continue from the always-fails case, remove `executor:failed`, make the fake succeed, tick. Expected: PR opened with the recorded title and body, no new agent step or test run, job done.
- `TestReopenPRBranchMoved`: after the failure, advance the branch tip, remove the label, tick. Expected: the full worker runs (an agent step happens).
- `TestReopenPRAlreadyExists`: a PR for the branch exists. Expected: fall through to the full run (or the existing PR path), and no duplicate PR.
- `TestCreatePRDryRun`: dry-run logs the retries only, with no effects call and no sleep.
- `TestCreatePRFailureNoPush` (update the existing `TestCreatePRFailure`): keeps `no_process` where nothing was pushed, and `pr_create_failed` where pushed.
- `internal/state/jobs_test.go` (or `store_test.go`): migration 0009 applies on a DB holding old rows; `PendingPR` round-trips; NULL reads as absent.
- `internal/closeout/cause_test.go`: `pr_create_failed` gives the failed plan, not a retry plan.
- Edge cases: context cancelled during backoff (no PR, no `executor:failed`), the first create succeeding on the server but returning an error (found by `ListPRs`), and a human removing the label before any record exists (today's path).

### Risk
Medium. The change adds a column to the controller's SQLite store (additive migration, old rows unaffected), a new close-out cause and a new agent-free finish path in the worker. The risk is mostly in the synthetic done close-out, which must not commit unvetted files; it only reuses the recorded, already redacted body and head. No secret-handling or merge-gate code changes, and there is no concurrency change beyond the loop's existing per-issue claim. None of the planned edits is on `merge.protected_paths`. The deployed `.ard/workers/engineer/prompt.txt` is protected, so a maintainer must sync the prompt rule by hand; the built-in template change here is safe on its own, because the agent-free path avoids the agent run in the common case.
