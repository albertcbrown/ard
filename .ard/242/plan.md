# Plan for #242

## Implementation

### Steps
1. `internal/budget/tokens.go` (new). Define `type TokenReader interface { RoleTokens(ctx, dayStart time.Time) (map[state.RoleKey]int64, error); RoleWorstTokens(ctx, k state.RoleKey) (int64, error) }` (both exist in `internal/state/usage.go`; `*state.Store` satisfies it). Add `func (g *Gate) SetTokenReader(r TokenReader)` (keeps `New`'s signature, so existing callers and tests compile). Add the pure rule `func tokenBlocked(used, cap, worst int64) bool { return used >= cap || cap-used < min(worst, cap) }` (U, C, W as in the issue). Add `func (g *Gate) tokenDenied(ctx, cfg, role, stage, dayStart) (bool, string)`: no cap from `cfg.RoleTokensPerDay(role)` means allow; read `RoleTokens` and `RoleWorstTokens`; any read error logs WARN `budget.read_failed` and returns refuse with `budget state unreadable`. Running jobs reserve nothing: only recorded usage counts. On a block, log `budget.blocked` once per cap and UTC day (reuse the `mu`/`logged` map with a `tokens|` key prefix) with role, used, cap, worst, and return a reason that holds numbers only.
2. `internal/budget/budget.go`: in `Denied`, after the existing scanner and no-role early returns (deterministic scanners with `ScanPath` stay exempt), run the dollar checks, then the token check. A refusal from either refuses the job. Reuse the one `dayStart`. If no token reader is set, skip the token check (a nil reader means no token caps are wired, not a failure). Update the package doc comment.
3. `internal/budget/tokens.go`: `type TokenCap struct { Stage, Role string; Used, Cap, Worst int64 }` and `func (g *Gate) TokenReport(ctx) ([]TokenCap, time.Time, error)`, returning every role with a token cap and its used, cap and worst figures, blocked or not, in config order, for #58 and a future `ard status`. Add `func (g *Gate) TokenCapped(ctx)` returning only the blocked ones (same rule as `tokenBlocked`). It logs nothing.
4. `internal/budget/notice.go`: make the `Capper` interface also return token caps, or add a second `TokenCapper` interface. `Deps` gets it; a nil value means no token notices. In `Tick`, for each blocked token cap, dedupe using the `budget_capped` event with `scope: "tokens"`, `stage`, `role` and `day` (the existing `noticeKey`), then call `CreateComment` with the new `RenderTokens(c TokenCap, day string)`. Keep `Render` and its `<!-- ard:budget scope=... -->` marker as they are. The token marker is exactly `<!-- ard:budget cap=tokens role=<kind>/<name> day=<YYYY-MM-DD> -->`; build `<kind>/<name>` from `safe()` values. The body holds only numbers, the day and config names, with no agent text and no `@`. The event data holds used, cap and worst. Check that the early return on `len(caps)==0` does not skip token caps.
5. `internal/servecmd/budget.go`: in `budgetGate()`, call `w.bgt.SetTokenReader(w.Store)` and pass the gate to the loop for token caps. `internal/servecmd/serve.go:300` already passes `w.budgetGate().Denied` to the pool, so no pool change is needed and the verdict stays `DeniedBudget` (`internal/pool/pool.go:26`). Fix the comments there ("daily dollar cap") to say "dollar or token cap".
6. `docs/proposal.md`: Guardrails "Budgets" bullet (about line 518): replace "nothing is enforced yet" with the rule (refuse when `U >= C` or `C - U < min(W, C)`; W is the role's largest reported job total; running jobs reserve nothing; scanners exempt; unreadable state refuses with `budget state unreadable`; once-a-day notice with its marker). Configuration (line 452): drop "recorded only, not enforced yet". Executors and the Reaper: add that the claim gate checks tokens as well as dollars, and that a running job is never killed for a token cap. There is a docs drift test in `make test`; check what it covers and keep the wording consistent.

### Test plan
Command: `make test` (or `go test ./internal/budget/... ./internal/servecmd/... ./internal/pool/...` while iterating). Use a fake clock and a fake token reader in `internal/budget/budget_test.go` and a new `internal/budget/tokens_test.go`.
- `TestTokenRule` (table, `tokens_test.go`): (U=0,C=100,W=50) allow; (U=50,C=100,W=50) allow, since C-U equals W; (U=51,C=100,W=50) block; (U=100,C=100,W=0) block; (W=500,C=100,U=0) allow, since min(W,C)=C and C-U=C; (W=500,C=100,U=1) block; W=0 (no history) blocks only at U>=C.
- `TestTokenBlocksOnlyThatRole`: two roles; the one below its worst case is refused, the other is allowed.
- `TestKimiTokenCapNoDollar`: a role with `tokens_per_day` and no dollar cap, with zero spend and unpriced steps, is refused by tokens alone.
- `TestBothCaps`: dollar failing with tokens ok, tokens failing with dollar ok, and both ok; the first two are refused and the last is allowed.
- `TestScannerExempt`: a deterministic scanner (`ScanPath`) is never checked, even with the repo cap set and the reader returning errors.
- `TestTokenReadFailsClosed`: reader error means refused, reason contains `budget state unreadable`, log has WARN `budget.read_failed`; also for the worst-tokens call failing.
- `TestTokenResetAtMidnightUTC`: used tokens at 23:59:59 block, and at 00:00:00 the next day they allow (the fake clock moves the day; the reader returns data per `dayStart`).
- `TestBlockedLoggedOncePerDay`: `budget.blocked` once per cap per day.
- `TestTokenReport` and `TestTokenCapped`: figures and order.
- `notice_test.go`: `TestTokenNoticeOncePerDay` (two ticks make one comment; the next day makes a second), `TestTokenNoticeMarker` (exact marker string, no `@`, unsafe names become `?`), `TestTokenNoticeRestart` (an existing `budget_capped` event stops a repeat), and a dollar notice that still renders as before.
- Edge cases: no token cap set; the repo-wide `tokens_per_day` default applies to roles without their own; a nil token reader; a dry run (ledger only).

### Risk
Medium. This is the claim path for every job, and the fail-closed branch (a read failure refuses all capped roles) can stall the pool if the store is unhealthy; the issue asks a human to review the rule table and that branch. No change touches `merge.protected_paths`, the database schema or the public CLI. `docs/proposal.md` is not protected. The gate is called from the pool's scheduling pass, and `Denied` already takes a mutex only for the log map, so keep the new reads outside that lock. Token reads add two queries per candidate; keep them cheap (consider reading `RoleWorstTokens` only when a cap is set, as planned).
