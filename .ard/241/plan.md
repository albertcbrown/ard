# Plan for #241

## Implementation

Revised for the owner decision: a job that ends without reported tokens is not charged. It is marked on the issue and the gap stays visible. There is no charge table, no `ChargeTokens`, no worst-case charge and no migration.

### Steps
1. **New `internal/config/tokens.go`**: `type TokenCount int64` with `ParseTokenCount(s string) (int64, error)`, `(*TokenCount).UnmarshalYAML(*yaml.Node)` and `MarshalYAML`, modelled on `Duration` in `internal/config/duration.go`. Accept a plain integer (YAML int or string) and a decimal with suffix `k`/`K` (x1e3) or `m`/`M` (x1e6): `40M`, `1.5M`, `500k`. Reject empty, zero, negative, non-numeric, unknown suffix, a result that is not a whole number of tokens (`1.5`) and overflow. Compute with integer/decimal arithmetic so `1.5M` is exactly 1500000. Every error names the offending string.
2. **`internal/config/raw.go`**: add `tokensPerDay *TokenCount` to the raw top-level struct and a `case "tokens_per_day":` using `decodeValue(...)` beside `budget_usd_per_day` (line ~113). **`internal/config/load.go`**: add `"tokens_per_day": true` to the allowed per-role override keys (line ~72), a `tokensPerDay *int64` field on the override struct, a separate parse case beside `"max_budget_usd", "budget_usd_per_day"` (line ~318; null ignored; must be > 0), and apply it next to `role.BudgetUSDPerDay` (line ~401).
3. **`internal/config/types.go`, `defaults.go`, `render.go`**: add `Role.TokensPerDay int64` (0 = unset) and `Resolved.TokensPerDay int64` (0 = no cap; no built-in default, so configs without the key stay uncapped and parse unchanged). `defaults.go` copies `raw.tokensPerDay` into `res`, with an error when set and <= 0. Add `func (r *Resolved) RoleTokensPerDay(role Role) (cap int64, set bool)` beside `RoleBudgetUSDPerDay` (types.go:228): the role value if > 0, else `r.TokensPerDay` if > 0, else `0, false`. In `render.go` add `tokens_per_day,omitempty` to the top-level (line ~28) and role (line ~108, ~124, ~174) structs so rendered output and `internal/config/testdata/resolved.golden` do not change when unset.
4. **`internal/state/usage.go`** (no migration, no schema or golden change):
   - `func (t Tokens) Counted() int64 { return t.Input + t.Output + t.CacheWrite }` (cache read excluded).
   - `func (s *Store) RoleTokens(ctx, dayStart time.Time) (map[RoleKey]int64, error)`: per (stage, role), the sum of counted columns of `step_usage` rows with `recorded_at >= dayStart`, joined to `jobs` for stage and role, using `COALESCE` for NULL columns. Mirrors `SpendSince` (usage.go:212); the caller supplies the UTC midnight. A step that reported no tokens has NULL columns and adds 0.
   - `func (s *Store) RoleWorstTokens(ctx, k RoleKey) (int64, error)`: the largest per-job sum of counted tokens over the role's `step_usage` rows, over all history; 0 when none. Reported usage only. #242 will read it.
5. **`internal/closeout/closeout.go`**: add `TokensUnreported bool \`json:",omitempty"\`` to `Job` (the record persists `Job`, so a resumed close-out keeps the flag). **`internal/closeout/comment.go`**: in `RenderComment`, when `j.TokensUnreported`, append a fixed-text line to `lines`, for example "Tokens not reported: this job's token use is not counted, so the day's token count for this role is low." It holds no agent text. It is written once with the comment; a resumed close-out re-renders the same persisted record, so it appears once. **`internal/closeout/facts.go`**: add `TokensUnreported bool` to `CostFacts` and set it from `rec.Job.TokensUnreported` in `FactsOf`. Check that `Run` on an existing open record (closeout.go ~400) keeps the stored Job rather than the new one; if it replaces it, take the flag from the stored record.
6. **`internal/costblock/costblock.go`**: add `TokensUnreported bool` to `Row`. In `rowLine`, when `Tokens` is nil (or invalid) and the flag is set, the tokens cell is `not reported` (instead of the dash). When tokens exist and the flag is set (an earlier step reported), append ` (partial)`. Extend `tokPat` use in `rowRE` to accept `not reported` and the `(partial)` suffix, and keep `Valid` strict; fold and total lines are unchanged. **`internal/costs/rows.go`**: set `r.TokensUnreported = f.TokensUnreported` in the `FactsOf` branch. A row with unreadable facts gets no mark.
7. **`internal/reaper/finish.go`**: in `FinishWith`, after the usage record/`JobUsage` block and before `CloseoutJob`, set `cj.TokensUnreported` true when all of these hold: `agentStep(jobID, h.JobID)`, `cause.Kind != closeout.CauseCloneFail`, `res.Usage == nil`, and the stored job has no step that reported tokens for this final step (i.e. the final step's own `StepUsageOf(res)` has `Tokens == nil`). Test steps (`<id>t<k>`) are excluded by `agentStep`. When it is set, log `f.log().Warn("reaper.tokens_unreported", "job", jobID, "stage", sj.Stage, "role", sj.Role)`. No `FinishStore` change and no charge. Log once per `FinishWith` call; a resumed close-out goes through `Closer.ResumeJob`, which does not pass here, so the log appears once.
8. **Docs `docs/proposal.md`**: in the configuration list and per-role keys text add `tokens_per_day` (accepts `40M`, `1.5M`, `500k` or plain integers; unset means no token cap; this part only records). In the Budgets bullet (line ~474) add: counted tokens are input + output + cache write, cache read excluded; a job that dies without reporting tokens is not counted and is marked "tokens not reported" on the issue, so a role can overshoot its token cap by such runs. Do not describe enforcement.

### Test plan
Command: `make test` (iterate with `go test ./internal/config/... ./internal/state/... ./internal/closeout/... ./internal/costblock/... ./internal/costs/... ./internal/reaper/...`), then `go vet ./...`.
- `internal/config/tokens_test.go` `TestTokenCount`: `40M`=40000000, `1.5M`=1500000, `500k`=500000, `500K`, `1234` as YAML int and as quoted string -> ok. `""`, `0`, `-5`, `abc`, `5g`, `1.5`, `1e6`, `9999999999999999999M` -> error naming the input.
- `internal/config/budget_test.go` or `load_test.go`: top-level `tokens_per_day: 40M` and a per-role `tokens_per_day: 500k` resolve via `RoleTokensPerDay` to role, then repo, then `(0,false)`; a config without the key parses unchanged and its render matches the existing golden; override `0`, negative and `abc` give an `Error` with file and key.
- `internal/state/usage_test.go`: `TestRoleTokens` (counted = in + out + cache write; cache read ignored; NULL tokens add 0; rows before `dayStart` excluded; same-name triage and worker roles stay separate); `TestRoleTokensDayBoundary` with the `Options.Now` fake clock (23:59:59 UTC counts for that day and not the next; 00:00:00 counts for the new day); `TestRoleWorstTokens` (max of per-job sums across steps, 0 with no jobs, steps that reported no tokens ignored); `TestTokensSurviveReopen` (close and reopen the store in the same dir, totals identical).
- `internal/closeout/comment_test.go`: a record with `TokensUnreported` renders the fixed line; without it no line. `facts` test: flag round-trips through the stored record, including a resumed close-out (mark appears once).
- `internal/costblock/costblock_test.go`: a row with the flag and no tokens renders `not reported` and `Valid` accepts it; flag with tokens renders `(partial)`; a hand-edited cell is still rejected.
- `internal/costs`: a closed job with the flag yields a row with the mark; one without does not.
- `internal/reaper/usage_test.go`: `TestFinishMarksUnreportedTokens` (agent final step, empty result -> `Job.TokensUnreported` set, `RoleTokens` unchanged, no row written anywhere else); `...NoMarkWhenTokensReported`; `...NoMarkForTestStep` (handle `<id>t1`); `...NoMarkForCloneFailed` (override `closeout.CauseCloneFail`); `...MarkOnceOnResume` (first `Run` errors, second succeeds; one marked comment).
- Edge: a job with an earlier fix step that reported tokens and a final step that did not is marked and counts the earlier tokens only. Failure: a failing `RecordStepUsage` does not fail close-out.

### Risk
Low to medium. No database migration or schema change. Additive config key, omitted when unset. The cost table block is parsed strictly, so the `rowRE` change must keep rejecting edited blocks (security-relevant, covered by tests). The close-out `Job` JSON gains an omitempty field, which is compatible with stored records. No protected path from `merge.protected_paths` is touched (only `docs/proposal.md` and Go code). No gating, so nothing can be blocked.
