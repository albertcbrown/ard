# Plan for #241

## Implementation

### Steps
1. **New `internal/config/tokens.go`**: `type TokenCount int64` with `ParseTokenCount(s string) (int64, error)` and `(*TokenCount).UnmarshalYAML(*yaml.Node)` and `MarshalYAML`, modelled on `Duration` in `internal/config/duration.go`. Accept plain integers (`40000000`, YAML int or string), and a decimal number with suffix `k`/`K` (x1e3) or `m`/`M` (x1e6) (`40M`, `1.5M`, `500k`). Reject empty, negative, zero, non-numeric, unknown suffix, a fractional result (e.g. `1.0005k` is fine only if it is a whole number of tokens) and overflow. Every error names the offending string. Compute the fractional case with integer/decimal arithmetic (or `math.Round` checked against an epsilon) so `1.5M` is exactly 1500000.
2. **`internal/config/raw.go`**: add `tokensPerDay *TokenCount` to the raw top-level struct and a `case "tokens_per_day":` using `decodeValue(value, cfgPath, name, &raw.tokensPerDay)` beside `budget_usd_per_day`. **`internal/config/load.go`**: add `"tokens_per_day": true` to the allowed per-role override keys (line ~72 map) for all kinds that already allow `budget_usd_per_day`, add `tokensPerDay *int64` to the override struct, and parse it in the `case "max_budget_usd", "budget_usd_per_day"` area (a separate case; null is ignored; must be greater than 0). Apply it in the role-override apply function next to `role.BudgetUSDPerDay`.
3. **`internal/config/types.go`, `defaults.go`, `render.go`**: add `Role.TokensPerDay int64` (zero = unset) and `Resolved.TokensPerDay int64` (zero = no cap; no built-in default, so configs without the key stay uncapped and parse unchanged). In `defaults.go` copy `raw.tokensPerDay` into `res.TokensPerDay` (error when set and <= 0). Add `func (r *Resolved) RoleTokensPerDay(role Role) (cap int64, set bool)`: role override if > 0, else `r.TokensPerDay` if > 0, else `0,false`. In `render.go` add `tokens_per_day` with `omitempty` to both the top-level and role structs so `ard config check`/render output of existing configs and goldens (`internal/config/testdata`) does not change when unset.
4. **New `internal/state/migrations/0008_tokens.sql`** (embedded by `migrationsFS` automatically): `CREATE TABLE token_charges(job_id TEXT PRIMARY KEY REFERENCES jobs(id) ON DELETE CASCADE, tokens INTEGER NOT NULL CHECK(tokens >= 0), recorded_at INTEGER NOT NULL);` plus `CREATE INDEX token_charges_recorded ON token_charges(recorded_at);`. Regenerate `internal/state/testdata/schema.golden` with `go test ./internal/state -run Golden -update` and review the diff.
5. **`internal/state/usage.go`** (new code, same file): 
   - `func (t Tokens) Counted() int64 { return t.Input + t.Output + t.CacheWrite }` (cache read excluded).
   - `func (s *Store) RoleTokens(ctx, dayStart time.Time) (map[RoleKey]int64, error)`: per (stage, role), the sum of counted columns of `step_usage` with `recorded_at >= dayStart` plus `token_charges.tokens` with `recorded_at >= dayStart` (join `jobs` for stage and role). Use `COALESCE` for NULL columns. Mirrors `SpendSince`; the caller supplies the UTC midnight.
   - `func (s *Store) RoleWorstTokens(ctx, k RoleKey) (int64, error)`: the maximum over that role's jobs of the job's summed counted tokens from `step_usage` only (charges are not recorded runs and never feed the worst case); 0 when the role has none. Uses all history, not just today.
   - `func (s *Store) ChargeTokens(ctx, jobID string, tokens int64) (bool, error)`: `INSERT ... ON CONFLICT(job_id) DO NOTHING`, `recorded_at = s.now().Unix()`; returns whether it inserted; error on negative tokens. Zero is a no-op returning false (do not insert a row).
6. **`internal/reaper/finish.go`**: add `RoleWorstTokens(ctx, state.RoleKey) (int64, error)` and `ChargeTokens(ctx, jobID string, tokens int64) (bool, error)` to `FinishStore` (existing test wrappers embed `*state.Store`, so they still satisfy it; check any other implementers with `go build ./... && go vet ./...`). In `FinishWith`, after the usage record/`JobUsage` block and before `CloseoutJob`, call a new unexported `f.chargeNoResult(ctx, sj, jobID, h, res, cause, totals, haveTotals)`. It runs only when `agentStep(jobID, h.JobID)`, `cause.Kind != closeout.CauseCloneFail`, `res.Usage == nil`, and `sj.Stage != "scanner"` unless scanner roles are agent roles (decide: charge any stage with an agent step, since scanners with LLMs run an agent step too; deterministic scanners have no worst case, W=0, so the charge is 0). Compute `W` from `RoleWorstTokens(RoleKey{sj.Stage, sj.Role})` and `recorded` from `totals.Tokens.Counted()` (0 when nil; when `haveTotals` is false, re-read `JobUsage` or skip with a warning). Charge `max(0, W - recorded)`. Log and ignore errors (`reaper.token_charge_failed`), as close-out never fails over accounting. Charging before `Closer.Run` makes a resumed close-out safe: the PK makes a second call a no-op, and a re-run after the crash charges once.
   - Note: do not charge when the final handle is a test step (`<id>t<k>`): `agentStep` already excludes it.
   - Also log `tokens_charged` in the `reaper.finish` attributes when > 0 (optional, small).
7. **Docs `docs/proposal.md`**: in the configuration list (line ~415 block and the per-role keys paragraph around line 445) add `tokens_per_day` (accepts `40M`, `1.5M`, `500k` or plain integers; unset means no token cap; no gating yet in this part, the ledger only records). Add one sentence to the Budgets bullet (~467) describing the ledger: counted tokens are input + output + cache write, cache read is excluded, a no-result agent job is charged its role's largest recorded run. Do not describe enforcement.

### Test plan
Command: `make test` (or `go test ./internal/config/... ./internal/state/... ./internal/reaper/...` while iterating; then `go vet ./...`).
- `internal/config/tokens_test.go` `TestTokenCount`: `40M`=40000000, `1.5M`=1500000, `500k`=500000, `500K`, `1234`=1234 as YAML int and quoted string -> ok. `""`, `0`, `-5`, `abc`, `5g`, `1.5` (fractional token), `1e6`, `9999999999999999999M` -> error naming the input.
- `internal/config/load_test.go` (follow existing budget tests in `budget_test.go`): top-level `tokens_per_day: 40M` and a per-role override `tokens_per_day: 500k` resolve through `RoleTokensPerDay` to role, then repo, then `(0,false)`; a config without the key resolves unchanged (compare an existing golden render); override `0`/negative/`abc` produces an `Error` with file and key; duplicate key still reported.
- `internal/state/usage_test.go`: `TestRoleTokens` (counted = in+out+cache write, cache read ignored; NULL tokens counted as 0; rows before `dayStart` excluded; separate roles and a same-name triage/worker pair stay separate by stage); `TestRoleTokensDayBoundary` with `Options.Now` fake clock: a step recorded at 23:59:59 UTC counts for that day and not for the next midnight; one at 00:00:00 counts for the new day; `TestRoleWorstTokens` (max of per-job sums across steps, 0 with no jobs, ignores charges); `TestChargeTokens` (first call true, repeat false and sum unchanged, negative errors, zero inserts nothing, charge counted in `RoleTokens`); `TestTokensSurviveReopen` (close and reopen the store in the same dir, totals identical).
- `internal/reaper/usage_test.go`: `TestFinishChargesWorstCaseWhenNoResult` (prior job of role has 100 counted tokens; new job with an empty agent result -> charged 100; `RoleTokens` reflects it); `...ChargesDifference` (job with a recorded earlier fix step of 30 -> charged 70); `...NoChargeWhenTokensReported`; `...NoChargeForTestStep` (handle `<id>t1`); `...NoChargeForCloneFailed` (override `closeout.CauseCloneFail`); `...NoChargeWhenWorstIsZero`; `TestChargeOnceOnResume` (call Finish twice, second with the closer returning an error the first time, then success; one charge row); `TestChargeErrorDoesNotFailCloseout` (wrapper returning an error from `ChargeTokens`, as in `failingRecord`).
- Edge: a job whose recorded tokens exceed W is charged 0; the worst case excludes the current job's own recorded steps being the max (then charge 0).

### Risk
Medium. New database migration (additive table, no data rewrite) and a regenerated schema golden. Touches the reaper close-out path, but errors are logged and ignored so close-out is unchanged on failure. Config parsing changes are additive and omitted when unset. `.ard/config.yaml` and other protected paths are not touched (only `docs/proposal.md`, which is not protected). No gating in this part, so no job can be blocked by it. SQLite writes happen outside the close-out transaction; concurrency is covered by the primary key.
