# Plan for #386

## Implementation

### Steps

Design anchors found in the code: part 2 (#385) left `closeout.Deps.Network` unset in `internal/servecmd/reaping.go` (`wiring.closer`); `closeout.Job.Network *NetworkState` and `NetworkRounds` already exist in `internal/closeout/network.go`; the pure `closeout.Build` (`internal/closeout/plan.go`) makes the triage `done` plan in its `default:` branch; `Prepare` (`internal/closeout/prepare.go`) is where state is read and persisted into the Record, so `Build` stays pure and `ResumeJob` replays the stored Plan.

1. **Round state types** (`internal/closeout/network.go`, new symbols). Extend `NetworkState` (zero-value compatible, `json:",omitempty"`, no `recordVersion` bump; add the new fields to the recordVersion comment in `closeout.go`):
   - `Round bool`: a network round is open, meaning the newest closed worker close-out of the issue has `Plan.Bounced` and no triage-engineer `done` close-out has closed after it.
   - `Done []string`: the other triage roles (not `lead`, not `engineer`) that finished `done` before; computed in `Prepare` from the issue's triage close-outs.
   Add `func NetworkRoundOpen(ctx, s closeoutsOf, issue int) (open bool, doneRoles []string, err error)` (new) reading `CloseoutsOf(issue, "triage")` and `"worker"` records via `decode`. "Consumed" is stored in the engineer's own Plan (step 3), so a later human re-request of the engineer sees no open round and does not re-arm.
2. **Plan fields** (`internal/closeout/plan.go`). Add to `Plan`: `Rearmed bool` (`json:",omitempty"`), `Rerun []string` (`json:",omitempty"`; roles whose `:done` the lead must remove, persisted), and `Inputs []Input` (see step 4). Add `type Input struct{ Path, Provider, URL string }` (new).
3. **Lead re-arm in `Build`** (`internal/closeout/plan.go`, `default:` branch, pure). When `j.Stage == StageTriage && j.Role == "engineer" && j.Network != nil && j.Network.Round`: set `p.Rearmed = true`, `p.Rerun = j.Network.Done`, and put into `p.Requests` the label `ard:pending` (`labels.Pending`) and into `p.Remove` `labels.Done(StageTriage, "lead")`, ordered before the engineer's own `:done` terminal label (check how `finish`/`request` in `closeout.go` order Requests, Remove and Terminal; Requests are applied in the request phase before Terminal, and the "remove X before :done" ordering for the bounce in part 2 shows removals precede it, so confirm `finish`'s order and add a test pinning it). In the lead's close-out (`j.Role == "lead"`), when `j.Network != nil && len(j.Network.Rerun) > 0`, append `Label{n, labels.Request(StageTriage, r)}` for each persisted role and `Label{n, labels.Done(StageTriage, r)}` removals for the same roles in the request phase, so the lead's request phase removes `:done` before the others run. Add `Rerun []string` to `NetworkState` for this (the lead job reads it from the same persisted round). Also make sure `:done` removal of an absent label is tolerated like `p.Bounced` does in `finish` (the `ErrNotFound` skip): extend that condition to `p.Rearmed || len(p.Rerun) > 0`.
4. **`inputs:` frontmatter** (`internal/closeout/rolefile.go`). Add `Inputs *[]rawInput \`yaml:"inputs"\`` to the raw struct (the known-keys list, strict decode like `fetched`), `RoleFile.Inputs []Input`, a validator `inputsOf` (new) modelled on `fetchedOf`: max 10 entries (`MaxInputs`), each `path` required, `provider` one of `human` or `worker` (document in proposal), `url` https-only with the same checks as `networkOf` (`MaxNetworkURL`). Allowed on triage `engineer` only (reject on other roles, as `fetched` is rejected on non-workers around line 299). Cleaning `path` here: reject with a `malformed(...)` error; the gate re-checks (step 6) because the Plan is the only trusted copy. Copy `rf.Inputs` into `p.Inputs` in `Build`.
5. **`Prepare` computes and persists the round** (`internal/closeout/prepare.go`, next to the part 2 block). For `j.Stage == StageTriage && d.Network != nil`: call `NetworkRoundOpen`; when the job is the engineer and rf.Status is `done`, set `j.Network = &NetworkState{Round: open, Done: doneRoles}`; when the job is the lead and a round is open (a bounce record newer than the engineer's last `done`, and the lead's Plan `Rearmed` was set by the engineer), set `j.Network = &NetworkState{Round: true, Rerun: <engineer plan's Rerun>}`. Keep part 2's worker branch unchanged. Because `Prepare` stores the resulting `Plan` in the Record before any label is applied, `ResumeJob` replays it without recomputing.
6. **Gate reads inputs from main** (`internal/triage/fanin.go`, `internal/triage/loop.go`, `internal/servecmd/triage.go`).

### Risk

High. It changes the label state machine and the stored job Record (new omitempty fields; no version bump, old records decode as zero), runs a controller loop that reads repository files from `main` driven by agent-written `inputs:` frontmatter (path-traversal and secret-path exposure; path checks must be enforced in the gate, not only at parse time), and switches on a bounce that retriggers triage jobs (cost and loop risk; the one-round guard from part 2 bounds it). Approval logic is security-sensitive: a network round must never start a worker without a fresh maintainer approval. Concurrency: the input cache is shared between ticks, so guard it with a mutex. Protected paths: none of the planned steps touches `merge.protected_paths`; the live engineer prompt under `.ard/triage/` is protected and is left for a human PR. The issue asks for a human architect review of the persisted round state and lead re-arm before this plan is approved.
