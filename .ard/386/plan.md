## Implementation

### Steps

Revised after the operator's architect review. Design anchors: part 2 (#385) left `closeout.Deps.Network` unset in `internal/servecmd/reaping.go` (`wiring.closer`); `closeout.Job.Network *NetworkState` and `NetworkRounds` exist in `internal/closeout/network.go`; the pure `closeout.Build` (`internal/closeout/plan.go`) makes the triage `done` plan in its `default:` branch (Terminal at plan.go ~141); `Prepare` (`internal/closeout/prepare.go`) persists state into the Record, so `Build` stays pure and `ResumeJob` replays the stored Plan. 1. **Round detection keys off the Plan, not the phase** (`internal/closeout/network.go`). Change `NetworkRounds` (and add `NetworkRoundCount`, `NetworkRoundOpen`) to count a worker record whose `Plan.Bounced` or `Plan.Outcome == OutcomeNeedsNetwork` from phase *prepared* onward (the Plan never changes after Prepare), not only `PhaseClosed`. This closes the fail-open where a crash leaves the worker record unclosed, the round reads as not open, nothing re-arms and, with `require_approval: false`, the gate starts the worker unapproved. Order records by job creation / ULID order, never `created_at` of `CloseoutsOf`: a round is open when the newest bounced worker record has no triage-engineer `done` record whose job ID sorts after it. New: `func NetworkRoundOpen(ctx, s closeoutsOf, issue int) (open bool, doneRoles []string, err error)` (doneRoles = other triage roles, not lead/engineer, with a `done` record), `func NetworkRoundCount(ctx, s closeoutsOf, issue int) (int, error)`.
2. **Plan and state fields** (`internal/closeout/plan.go`, `network.go`, `closeout.go`). Add to `Plan`: `Rearmed bool`, `Rerun []string` (roles the lead must re-open; persisted), `Clear []Label` (removed in the request phase), `Inputs []Input`; new `type Input struct{ Path, Provider, URL string }`. All `json:",omitempty"`, no `recordVersion` bump; extend the compatibility comment in `closeout.go` ~25. Extend `NetworkState` with `Round bool` and `Done []string`.
3. **`Clear` in the request phase** (`internal/closeout/closeout.go`). In `finish` (~817-829) Terminal (`:done`) is added first and `Remove` runs after it, while `request` (~691) only adds, so a removal "before `:done`" cannot come from `p.Remove`. Make `request` also remove every label in `p.Clear` before the request labels are added; a 404 (`github.ErrNotFound`) counts as success per label. Do not widen the `p.Bounced` skip in `finish` to the whole plan (a missing `:running` must still fail). Test pinning the order: Clear removals, then Requests, then Terminal, then Remove.
4. **Re-arm in `Build`** (`plan.go`, `default:` branch). Engineer (`j.Stage == StageTriage && j.Role == "engineer"`, status done) with `j.Network != nil && j.Network.Round`: `p.Rearmed = true`, `p.Rerun = j.Network.Done`, `Requests` gets `labels.Pending`, `Clear` gets `labels.Done(StageTriage, "lead")`. The round is consumed by that engineer `done`, so a human re-request of the engineer sees no open round and does not re-arm again. Lead close-out: when `j.Network != nil && len(j.Network.Rerun) > 0`, `Requests` gets `labels.Request(StageTriage, r)` and `Clear` gets `labels.Done(StageTriage, r)` for each role in `Rerun` filtered to roles configured in the job's role set (a deleted role must not end `unknown-role`); the lead's own `:done` is Terminal as usual.
5. **`Prepare` computes and persists the round** (`prepare.go`, next to the part 2 block). For triage jobs with `d.Network != nil`: engineer `done` sets `j.Network = &NetworkState{Round: open, Done: doneRoles}`. Lead: new `func LeadRerun(ctx, s closeoutsOf, issue int) ([]string, error)` (network.go) returns the `Rerun` of the newest triage-engineer record with `Plan.Rearmed`, only if no lead `done` job was created after it (ULID order); `Prepare` sets `j.Network = &NetworkState{Rerun: ...}` from it. The lead cannot use `NetworkRoundOpen` here: once the engineer is closed the round is already consumed. Build must not read the store.

### Risk

High. It changes the label state machine (new `Clear` phase) and the stored job Record (omitempty fields, no version bump), reads repository paths from `main` from agent-written `inputs:` (path traversal, secret-path exposure; checks enforced in the gate, not only at parse time), and switches on a bounce that retriggers triage (cost and loop risk bounded by the part 2 one-round guard). Security-sensitive: a network round must never start a worker without a fresh approval, so round detection must not depend on the close-out phase. Concurrency: the SHA-keyed cache is shared across ticks and needs a mutex. Protected paths: none touched (`.ard/triage/` live prompt left for a human). No public interface migrations beyond new `triage.Deps` fields.
