# Plan for #348

## Implementation

### Steps

1. **New `internal/effects` method `SetRepoVariable`.** In `internal/effects/effects.go` add to `Effects`: `SetRepoVariable(ctx context.Context, repo, name, value string) error` (new). Put it beside `ApproveIssue`, not in `github.Writer`, so the App client can never reach it (the App cannot write variables). Implement in a new `internal/effects/variable.go`: `(*Live).SetRepoVariable` validates `repo` with `repopath.Parts`, and a `name` matching `^[A-Z][A-Z0-9_]*$`, then creates or updates the Actions variable (PATCH `repos/{o}/{r}/actions/variables/{name}`, falling back to POST on 404) using the operator token, through go-github (`Actions.CreateRepoVariable` / `UpdateRepoVariable`) on a client built from the token. `(*DryRun).SetRepoVariable` calls `d.emit(ctx, "SetRepoVariable", repo, map[string]any{"name": name, "value": value}, false, nil)` and does nothing else. Log through `l.done`, never the token. Update every other `Effects` implementation or fake (`grep -rn "ApproveIssue" internal` shows them; also `internal/effects/archtest` if it lists methods) so the build passes.
2. **Operator token plumbing.** Add `OperatorToken func(ctx context.Context) (string, error)` to `effects.Options` (`internal/effects/open.go`) and a matching field on `Live` (set via a new option or setter next to `NewLive`). `Live.SetRepoVariable` calls it only when invoked, so the token is read once, held in memory, never logged or stored. When it is nil or fails, return a new exported `effects.ErrNoOperatorToken` with a message naming `ARD_GITHUB_TOKEN` (PAT) and `gh auth login`. In `internal/setupcmd/cmd.go` `Command`, build the func from the existing `github.GhFallback` (`internal/github/ghcli.go`, uses `gh auth token --hostname github.com`) or a PAT `TokenAuth` from `github.AuthFromEnv` when the configured auth is a PAT. Reuse what #302 already put in `internal/github/auth.go`; do not add a second token reader. If the configured auth is the App, use the gh fallback.
3. **Embedded workflow.** New directory `internal/setupcmd/workflow/` (new) with `bot-commits.yml`, a byte-for-byte copy of `.github/workflows/bot-commits.yml` (copying into a new path is allowed; do not edit `.github/`). New `internal/setupcmd/workflow.go`: `//go:embed workflow/bot-commits.yml` into `var botCommitsWorkflow []byte`, `const workflowPath = ".github/workflows/bot-commits.yml"`, and `PrintWorkflow(w io.Writer) error` writing the bytes.
4. **Workflow check row.** In `workflow.go` add `func checkWorkflow(ctx, fileAt func(ctx, rev, path string) ([]byte, bool, error)) Row` (name `workflow`). Absent on `origin/main` gives `StatusManual` with detail `commit .github/workflows/bot-commits.yml: run ard setup --print-workflow > .github/workflows/bot-commits.yml, then open a PR`. Different bytes (compare after normalising CRLF to LF) gives `StatusManual`, with the same fix and "differs from the copy embedded in ard". Equal gives `StatusOK`. If `origin/main` does not exist, give a `StatusManual` row saying it could not be checked (fetch first), never a hard failure. Add `Deps.WorkflowAt func(ctx context.Context) ([]byte, bool, error)` (new) in `internal/setupcmd/setup.go`; wire it in `cmd.go` with `gitx.New("").FileAt(ctx, root, "origin/main", workflowPath, 1<<20)` (`internal/gitx/local.go`). Append the row in `Run` after the policy rows, before the label step, only when `WorkflowAt != nil`. Setup never commits and never writes `.github/`.
5. **ARD_BOT_LOGIN row and apply.** In `internal/setupcmd/setup.go` add `Deps.Variables VariableWriter` (new interface `SetRepoVariable(ctx, repo, name, value string) error`) and `Deps.Confirm func(prompt string) (bool, error)` (new). Add `botLoginVar = "ARD_BOT_LOGIN"` in `policy.go`. New `botLoginRow` in `workflow.go` or a new `botlogin.go`: want is `id.Login`, taken from `Policy.Identity` (already used in `policyRows`; make sure it ends in `[bot]`, otherwise a `StatusManual` row "ard is not running as a GitHub App; ARD_BOT_LOGIN needs the App's <slug>[bot] login"). Never read config for it. Read the current value with `Policy.GetVariable`. Absent gives `StatusDrift` ("not set; will set to <want>"). Equal gives ok. Different gives `StatusDrift` ("is <have>, App is <want>"). Soft errors (`ErrForbidden`, `ErrNotFound`) give a manual row with `gh variable set ARD_BOT_LOGIN -R <repo> --body <want>`. Apply, in `Run`, after the checks, only when not `Check`, not blocked, and the row is drift: absent, call `SetRepoVariable`; different, call `Confirm` first and skip with a `StatusManual` row (fix command in detail) when it answers no or is nil. Under dry-run the writer logs only and the row says "would set". `ErrNoOperatorToken` or a write error becomes a manual row with the `gh variable set` command, not an abort. Set the variable before the labels so a label failure does not hide it.
6. **Confirmation prompt.** In `cmd.go` build `Confirm` from `e.Stdin` if `cli.Env` has it (check `internal/cli/app.go`; if it has no stdin or the input is not a terminal, return false so the run never blocks or overwrites silently). Add `--yes` only if the existing `cli.Env` has no prompt helper to reuse; otherwise keep to the flags in step 7.
7. **`--print-workflow` flag.** In `internal/cli/app.go` add `PrintWorkflow bool` to `SetupOpts`. In `internal/cli/cmd_setup.go` register `f.BoolVar(&o.PrintWorkflow, "print-workflow", false, "print the bot-commits workflow embedded in ard and exit")`; reject combinations with `--check`, `--create-gh-app` and the App flags. In `setupcmd.Command` handle it first, before config load, repo resolution or any credentials: `return PrintWorkflow(e.Stdout)`. Nothing else may be written to stdout in that mode, so a redirect to a file is clean.
8. **Docs.** Update `docs/proposal.md` paragraph "`ard setup` applies `.ard/` to GitHub" (add the `--print-workflow` flag, confirm-before-overwrite and the manual rows), `docs/runbooks/onboard-repo.md` (steps 49 and 50: use `ard setup --print-workflow` and let setup set the variable), `docs/site/getting-started.md` line 61, and `internal/initcmd/body.go` lines 64 to 65 only if the wording should mention `ard setup`. If you change `body.go`, update the matching string checks in `internal/initcmd/initcmd_test.go`. Add the `workflow/` directory to `docs/layout.md` under `internal/setupcmd/`.

### Risk

Medium. It adds a credentialed write (an Actions variable) through the operator's token, so the token must stay in memory and out of logs and errors. `ARD_BOT_LOGIN` is the control input of the bot-commits audit: a wrong value silently disables the audit, so the value must come only from the App identity and an existing different value is never overwritten without confirmation. It extends the public `Effects` interface and `SetupOpts`. No `.github/` or `merge.protected_paths` file is edited: the workflow is only read and copied. No migrations or concurrency changes.
