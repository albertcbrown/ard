# Plan for #302

## Implementation

Decision on self-review (the one open choice): no reviewer change is needed. `internal/reviewer` already posts every review with event COMMENT (`github.ReviewInput` is "always posted with event COMMENT"), and ard's verdicts are gated on its own `.ard/<issue#>/` records, not on GitHub approvals. The only approval gate is the merger's protected-path check, `approved()` in `internal/merger/gates.go`, which already ignores reviews by `self` (ard's login). With a PAT, `self` is the token's user, so that user's own approval is ignored (GitHub also forbids approving your own PR). Behaviour: **a PAT setup needs protected-path approvals from a different write-access user**; the docs say so and a test pins it. A maintainer may want to confirm this.

### Steps

1. `internal/github/auth.go`: update the `Auth` and `TokenAuth` comments (PAT is supported for live runs; "Development only" goes). Add `func NewTokenAuthFrom(token string, src string) *TokenAuth` or a `Source string` field on `TokenAuth` (new; values `env`, `gh`) so the startup log can say where the PAT came from. `Value` must never be formatted: add `func (*TokenAuth) String() string` and `GoString()` returning `token(<source>)` (new) so an accidental `%v` or `%+v` cannot leak it. Keep `AuthFromEnv` unchanged, and keep `ErrNoCredentials` as its "nothing set" result.
2. New `internal/github/ghcli.go`: `func GhFallback(ctx context.Context, lookPath func(string) (string, error), run func(ctx context.Context, name string, args ...string) ([]byte, error), out io.Writer) (*TokenAuth, error)`. It runs `gh` via `lookPath("gh")`. Not found: return a new `ErrNoGh`, whose message lists both ways to configure auth (GitHub App variables, or `ARD_GITHUB_TOKEN`) and says `gh` is not installed. Found: run `gh auth status --hostname github.com`; on a non-zero exit return a new `ErrGhNotLoggedIn` carrying the text `gh auth login --hostname github.com --git-protocol https --scopes repo`. Logged in: print to `out` that ard will use the `gh` token for this session and run `gh auth token --hostname github.com`, read it once, trim it, and return `&TokenAuth{Value: tok, Source: "gh"}`. An empty output is an error. Never include the token or the command's stderr in an error (stderr may echo it); wrap only exit status. The `run` seam lets tests avoid a real `gh`, but also add a test with a fake `gh` script on `PATH` (acceptance criterion).
3. New `internal/github/connect.go`: `type Connection struct{ Kind AuthKind; Login string; Repo Repo; Permissions map[string]string; Scopes []string }` and `func Connect(ctx context.Context, cfg Config) (Connection, error)`. It resolves auth against `GET /repos/{owner}/{repo}` using the same HTTP transport as `New`. Token: read `permissions` from the repo response (admin/push/pull, which map to write/read) and, for a classic PAT, the `X-OAuth-Scopes` header (needs `repo`; the header is absent for fine-grained tokens, so fall back to the repo `permissions` push flag plus probes below). App: call `GET /repos/{o}/{r}/installation` with the JWT transport (`AppAuth.discover` already does this) then read installation `permissions` for contents, issues, pull_requests (write), checks, statuses (read; "write" also satisfies). Fine-grained PATs expose no permission list, so verify issues and PR access with one cheap read each (`ListLabels` and a `ListPRs` with per page 1) and say "could not verify X" only when those fail. Return typed errors (new, in `internal/github/errors.go`): `ConnectError{Kind: no-credentials|bad-key|app-not-installed|missing-permission|repo-not-found|unauthorized, Detail string}` whose `Error()` is one line naming what is missing, built from fixed strings and permission names only (never a response body, header or token). Map 401 to unauthorized, 404 to repo-not-found (for tokens, say it may also mean the token cannot see a private repo), 404 on installation to app-not-installed, and PEM or JWT errors to bad-key.
4. `internal/servecmd/serve.go` `buildDeps`: replace the dry-run-only refusal (lines around 538-544). Resolve auth: `AuthFromEnv`; on `ErrNoCredentials` call `github.GhFallback(ctx, exec.LookPath, runCmd, e.Stderr)`; on `ErrNoGh` or `ErrGhNotLoggedIn` return `&cli.ExitError{Code: 1, Err: ...}` with that text. Make the `gh` seams package variables (`lookPath`, `runGh`) so tests override them. Then call `github.Connect` before `effects.Open`, so a failure exits non-zero before any loop starts, and log once: `e.Log.Info("github.connect", "auth", kind, "source", src, "login", login, "repo", repo.String(), "permissions", perms)`. Dry-run still builds a read-only client; the connect check also runs in dry-run but demands only read permissions then. Add the `gh` token to the redactor: `redact.New(append(redact.FromEnviron(os.Environ()), <token>)...)` in the form `redact.New` accepts (read `internal/redact` for the exact constructor; the token is not in the environment, so `FromEnviron` will not see it). Make sure the token reaches `deps.Token` only (used for git push by the controller) and is not copied to any job spec or executor env; `github.EnvNames` already strips the ARD_ variables and the `gh` token never enters the environment. Also set `GH_TOKEN`/`GITHUB_TOKEN` in the executor's strip list if they are not already stripped (check `internal/executor/local`).
5. `internal/servecmd/serve.go` (`serve.start` log near line 331): add `identity` (login from `d.Reader.Identity`) and `auth` fields. The `status-issue` startup hook already calls `Identity`; reuse the result rather than calling twice (the client caches it).
6. `internal/configcmd/config.go`: after the existing checks, report which identity ard would act as without calling GitHub when no network is wanted. Keep `ard config check` offline: print one stderr line `ard config check: github auth: app (ARD_GITHUB_APP_ID set)`, `token (ARD_GITHUB_TOKEN)`, or `none (ard serve will try gh)`; it reads only environment variable presence via `github.AuthFromEnv`, and never runs `gh` or the network. A malformed App variable set is a load error as today.
7. `internal/merger/gates.go`: no logic change. Add a doc comment on `approvalCheck.self` stating that under PAT auth it is the user's login, so that user's own approval does not count.
8. Docs: `docs/proposal.md` (Guardrails: Identity, line ~493): replace the "accepted only for local --dry-run" sentence with both identities and the PAT trade-offs from the issue (identity of actions, self-review decision above, bot-commit audit cannot distinguish main-lane commits, workflows backstop, expiry and a recommended single-repo fine-grained PAT with an expiry), plus the `gh` fallback and that the token is memory-only. Update the CLAUDE.md-independent places: `README.md` (three ways to start), `docs/site/getting-started.md`, `docs/site/operations/gate-2-runbook.md` and `docs/runbooks/onboard-repo.md` where they mention `ARD_GITHUB_*`. Do NOT edit `.github/workflows/bot-commits.yml` (protected). Update `docs/layout.md` only if a package is added (none planned). Do not edit CLAUDE.md (protected path); its stack line says "GitHub App installation token" and a maintainer should update it by hand.

### Test plan

### Risk

Medium. Security-sensitive: credential handling, and invariant 2 (agents hold no token) and invariant 7 (redaction) must hold for the new in-memory `gh` token. It relaxes the existing live-run refusal, so the startup check is the new safety net. Self-review changes no code, only docs and a test, but a PAT user cannot approve protected-path PRs. No protected path from merge.protected_paths is touched (`.github/`, CLAUDE.md and `.ard/config.yaml` are left alone). No migrations. Concurrency is low: the check runs once before loops start.
