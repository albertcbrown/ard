# Plan for #406

## Implementation

### Steps
1. `internal/config/types.go`, `raw.go`, `defaults.go`, `render.go`: add `Approvals` to `Intervals` (new, default 1m via new `defaultIntervalApprovals`), `approvals` to `rawIntervals.parse` (both the `set(...)` call and the accepted-key switch and its "unknown key" message), `intervalOr` in the resolve step and the minimum-1m check list (`intervals.approvals`), and `intervalsYAML`/`Intervals` rendering. Reason: the schema rejects unknown keys, so the key must exist before use.
2. `internal/controller/controller.go`: add exported `func (c *Controller) WakeLoops(reason string, names ...string)`. It sends non-blocking on each named runner's existing `r.wake` channel (capacity 1, so pending wakes merge; a loop mid-tick runs once more, as for #394), ignores unknown names and calls after shutdown, and logs `controller.wake` with `reason` and the loops actually woken. Keep the runners reachable from the Controller (store them in a field set in `Run`, guarded by `c.mu`). Add a short debounce reusing the `wakeOnFreed` pattern (`FreedDebounce`/`DefaultFreedDebounce`): collect the names requested within the window into a set, then wake once per loop. Paused handling stays in `runner` tick code, so a wake while paused does nothing; check that path in `scheduler.go` and do not add a bypass.
3. `internal/controller` (new `approvals.go`): `ApprovalWatch` loop-like goroutine started from `Run`. Deps: a `Search func(ctx, q string) ([]github.Issue, error)` (from `github.Reader.SearchIssues`), clock, interval, `DryRun`-agnostic since it only reads. Each interval run searches, in one or a few queries: `is:open label:ard:approved -label:ard:worker:*` (use the prefix exclusion as the label catalogue allows; otherwise filter in Go by `labels` package), plus open items carrying a triage-done label, and items that lost `ard:needs-human` or `ard:executor:failed`. Removal cannot be searched directly, so for the unblock case find items with `ard:triage:*:done`/worker/review `request` or `done` state and no `needs-human`/`executor:failed`, and keep an in-memory "seen with needs-human or executor:failed" set; a later absence wakes the owning loop (`reason=unblocked`). Worker must confirm exact queries against `internal/labels` and what `triage/loop.go`, `workers` and `reviewer/loop.go` already search for. A hit on approval wakes `triage` (`reason=approval`); an unblocked item wakes the loop that owns its stage label. Skip when the kill switch is on (use the same `Pauser` as ticks) and do nothing but read in dry-run. Errors are logged and retried next interval; no agent, no slot.
4. `internal/servecmd/serve.go`: wire the watch into `controller.Deps` (new field e.g. `Approvals *ApprovalWatchDeps`) with `d.Reader.SearchIssues` and `cfg.Intervals.Approvals` read from the fresh config each run; register `approvals` in `knownLoops` only if it should be selectable with `--loops`, otherwise leave it implicit. Give `controller.Controller` to the closer via a late-bound hook (the Controller is built after the closer), e.g. a `wiring.wake atomic.Pointer[func(reason string, names ...string)]` set after `controller.New`.
5. `internal/closeout/closeout.go`: add `Deps.Wake func(reason string, names ...string)` (optional, nil skips). In `advance`, after `c.finish` succeeds (and before or after `PhaseClosed` is saved; do it once, also on resume paths; a double wake is harmless) compute loops from `rec.Plan`: `Requests` and `Terminal` with `ard:worker:*` → `workers`; `ard:review:*` → `reviewers`; `ard:triage:*` or `ard:pending` → `triage`; a PR marked ready (find the effect in `postReview`/`review.go`) → `merger`; a review round request (changes requested, see `ReviewChanged`) → `workers` (and `reviewfix` if that loop owns it). Add pure helper `func WakeTargets(p Plan, j Job) []string` (new) so it is unit-testable. Skip on dry-run and on failed/retry outcomes. Reason `closeout`.
6. `internal/servecmd/reaping.go`: pass `Wake` in `closeout.New(closeout.Deps{...})`, delegating to the late-bound controller hook from step 4.
7. `docs/proposal.md`: update the triage gate, worker and reviewer loop sections, "One pool of job slots" (line ~310) and the Configuration intervals table (new `intervals.approvals`, default 1m, minimum 1m): hand-offs wake the next loop, approvals are polled by the watch, the gate still does the real check. Also update the comment about intervals in config docs if any (`ard config check` text).

No migrations. No path in `merge.protected_paths` is touched; the stopgap interval change in `.ard/config.yaml` is a separate human PR.
