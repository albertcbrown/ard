# Plan for #416

## Implementation

### Steps
1. `internal/effects/effects.go` (edit): add to the `Effects` interface `ApproveIssue(ctx context.Context, repo string, n int) error` ("run the operator's own gh to add `ard:approved`"). Do NOT add it to `github.Writer`, so the App client can never reach it. `Live` and `DryRun` both must implement it, so steps 2 and 3 go in the same commit as this one.
2. `internal/effects/live.go` (edit) and new `internal/effects/approve.go`: `Live.ApproveIssue` rejects n <= 0 with `bad("ApproveIssue", n)`, validates `repo` as `owner/name` (use `internal/repopath` if it fits, else a strict regexp), then runs `exec.CommandContext(ctx, "gh", "issue", "edit", strconv.Itoa(n), "--add-label", labels.Approved, "-R", repo)` with no shell. The environment is inherited so gh uses the operator's own login; ard never reads a token. Add a package var `ghPath = exec.LookPath` for tests. Add sentinel `ErrGHUnavailable`, returned when gh is not on PATH or its stderr shows it is not logged in (`gh auth status` non-zero is a fine pre-check). Log via `l.done(ctx, "ApproveIssue", n, err, "repo", repo)`.
3. `internal/effects/dryrun.go` (edit): `DryRun.ApproveIssue` calls `d.emit(ctx, "ApproveIssue", repo, map[string]any{"issue": n, "label": labels.Approved}, false, nil)` and runs nothing. Check `internal/effects/ledger.go` for any op allow-list and extend it. Check `internal/effects/archtest` still passes (exec use is allowed only inside effects).
4. `internal/snapshot/snapshot.go` (edit): new type `QueueItem{Issue int; Title, Role, PlanURL string}` and field `Snapshot.Queue []QueueItem` (new). The snapshot must not call GitHub, so fill it from a new in-memory source `Sources.Approvals` (new interface `Queue() []QueueItem`). If #407/#414 already defined a queue field in IssueView, use that instead and skip this step. Titles are stored raw here; the UI sanitises.
5. `internal/triage/fanin.go` (edit): in `askApproval` (line ~451) record the issue in the queue (number, title from the `github.Issue` that `approved` already has, worker role, plan link `https://github.com/<repo>/blob/main/.ard/<n>/plan.md`). Remove it when `approved` returns true, the label is present, or the issue closes or gets `ard:needs-human`. Guard with a mutex. Keep it a small new type `triage.ApprovalQueue` (new, in `internal/triage/queue.go`) with `Add`, `Remove`, `Snapshot`; wire it in `internal/servecmd/serve.go` and `internal/servecmd/snapshot.go` beside the existing snapshot Sources.
6. `internal/ui/model.go` and `internal/ui/keys.go` (edit): `New` gets an `approve func(n int) error` field (via a new option or an extra parameter; update `internal/servecmd/ui.go` and the tests' callers). Add `confirmApprove *snapshot.QueueItem` state. In `handleKey`, `a` acts only when the selected issue number is in `m.snap.Queue`; otherwise it is ignored. While the confirm screen is open: `y` runs approve and closes it; Esc, `n`, Enter and every other key cancel (default No). Ctrl-C still quits. Add `a approve` to the help text.
7. `internal/ui/view.go` and `internal/ui/sanitize.go` (edit): render the confirm screen with number, title, worker role and plan link, all through the existing sanitiser, showing "Approve? [y/N]". Show the result line ("approved #N", or an error) in the footer.
8. `internal/servecmd/ui.go` (edit) and `internal/servecmd/approve.go` (new): `approveFn(w *wiring, repo)` calls `Effects.ApproveIssue`. On success it calls `w.wakeLoops("ui-approve", "triage")` (the triage loop name is "triage"; see `internal/servecmd/loops_test.go`). On `ErrGHUnavailable` it shows `ui.IssueURL(repo, n)` in the status line and calls `ui.OpenBrowser`. Pass this to `ui.New`; `runWithUI` gets the new parameter.
9. `docs/proposal.md` (edit): add one sentence to the approval paragraph (the one with "ready for approval", ~line 287) saying that `ard serve`'s `a` key runs the operator's own `gh issue edit` (or opens the issue URL when gh is missing), that the App never adds `ard:approved`, and that dry-run records the effect. `internal/docscheck` runs in `make lint test`, so run it and keep its conventions.

### Test plan
Command: `make lint test` (workers/engineer override in .ard/config.yaml).
- `internal/effects/approve_test.go`: `TestApproveIssueRunsGH` puts a fake `gh` script on PATH (via `t.Setenv("PATH", dir)`) that records argv. Expect exactly `issue edit 42 --add-label ard:approved -R o/r`. `TestApproveIssueNoGH` with an empty PATH returns `ErrGHUnavailable`. `TestApproveIssueBadInput`: n=0, n=-1 and repo `o/r;rm` return an error and run nothing. `TestDryRunApproveRecords`: the ledger holds an `ApproveIssue` record, the fake gh was never run, and no client write was called. `TestApproveNeverUsesAppClient`: with `failClient` (see effects_test.go:32) as the client, `Live.ApproveIssue` makes no client call.
- `internal/ui/ui_test.go`: `a` on a queue row opens the confirm screen (golden file in `internal/ui/testdata`); `y` calls approve once with the number; Esc, Enter, `n` and a random key call it zero times; `a` on a non-queue row and on an empty list does nothing; a hostile title (ANSI escapes, newline) renders sanitised.
- `internal/servecmd`: approve success wakes triage once (use a fake controller or wake hook); `ErrGHUnavailable` calls the fake opener with the issue URL; dry-run wake is harmless.
- `internal/triage`: `askApproval` adds the issue to the queue and `approved` removes it; a repeat does not duplicate it.
- `internal/snapshot`: the import test must still pass (no `internal/github` import); `Queue` is filled from the source.

### Risk
Medium. The change spawns a subprocess with the operator's credentials, so arguments must come only from the integer issue number, the constant label and the validated repo. It touches the `Effects` interface (every implementation and fake must compile) and adds shared state between the triage loop and the UI (mutex). No file under `merge.protected_paths` is touched (`docs/proposal.md` and `internal/` are not listed). There are no migrations. Approval is still enforced by the existing gate (actor permission, after the triage `:done`), so a UI approval cannot bypass it.
