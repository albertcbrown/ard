4. **New paragraph "Kubernetes-executor details"** right after the table, in the style of "Local-executor details". Record revision 3:
   - Flow and pod shape: `pre` (token via `http.extraheader` from the environment, never argv or `.git/config`; git dir on a `ctl` volume the agent does not mount; role dir from `cfg.SHA`, so k8s refuses a config without a SHA; sidecars at pinned SHAs; untrusted inputs and scrub list in the per-job Secret, capped at 768 KiB, over the cap a permanent failure with a named cause; copies the static `ard` binary); `agent` (mounts only `work` and `out`, holds only its model credential via `secretKeyRef`, no GitHub token, key, Secret volume or SA token; tees stdout to `out/stdout`, enforces its deadline, writes a done marker, reaps orphans as PID 1); `post` (own pinned image, never runs a binary from a shared volume; one route `GET /v1/result` on the pod IP, preshared 32-byte `crypto/rand` key unique to the pod, mounted only in `post`, kept in memory by the controller, constant-time compare; 409 until the agent has terminated and the marker exists; builds the tar in Go, never runs git; one concurrent request; header/idle timeouts; never logs Authorization; exits 0 after the controller confirms or the deadline). Plain HTTP inside the cluster, because the key grants only this job's result and NetworkPolicy limits who can connect.
   - Controller: `Prepare` builds the local workspace; mints the read token, key and per-job Secret (owned by the Pod); revokes the token (`DELETE /installation/token`) after `pre` terminates; tokens join the redaction set. Completion is decided only from the kubelet (`containerStatuses`, agent `state.terminated`), never from the agent-writable done marker; the controller then pulls the result and safe-untars into `<id>.result` (rules: `os.Root`, regular files/dirs/symlinks with symlinks last, modes masked to 0644/0755, reject hardlinks, devices, FIFOs, `..`, absolute paths, NUL, duplicates, any `.git` component, case-fold collisions; caps on compressed and decompressed bytes counted on the stream, entry count, per-file size, gzip ratio). Close-out runs unchanged (`gitx.Snapshot` against `BaseSHA`). Exit code comes from the kubelet only and is saved in `<id>.done` (gap 14); a pod that ends with no valid result is `Gone`, never `Exited` 0. Statuses: `Running`, `Orphaned`, `Exited`, `TimedOut`, `Gone`. Requires GitHub App auth (a PAT cannot be scoped down). Keys are not persisted: after a restart the Reaper kills orphan pods, and a sweep by an `ard/repo` hash label finds pods with no state record (gap 16). Handles of the other executor kind report `Gone` (gap 15). Pod and job names: lowercased id, `ard-<id>` at most 63 so ids over 59 are rejected (gap 12). Client: thin REST client over the in-cluster SA token behind an interface with a fake, no client-go.
   - Layout and limits: pod paths `/job`, `/work`, `/role`, `/sidecar`, `/ard-config`, `/ard-out`, `/ard-bin`; result roots `work/` and `out/` (stdout at `out/stdout`, outside `work/`, so it never shows in `Snapshot.Changed`; gap 2). Defaults: 2 GiB `emptyDir` per pod, result 512 MiB compressed and 2 GiB unpacked, 200k files, 100 MiB per file, all overridable by `ard serve` flags (gap 19).
   - Deadlines (gap 13): `h.Deadline = Start + Timeout`; job-exec deadline `h.Deadline - min(2m, Timeout/10)`; pod `activeDeadlineSeconds = Timeout + UploadGrace` (2 min; name it as the result-pull grace); key revoked at `Deadline + grace`; job-exec exits 124 at its deadline, which maps to `TimedOut`.
   - Settings and images: cluster settings (jobs namespace, images, sizes) are `ard serve` flags set by the chart, not `.ard/config.yaml`; `executor` is fixed at startup and a later config with a different value is a config error until restart (gap 6). The `ard-agent` image is public under `ghcr.io/albertcbrown/ard`, holds no secrets (an image test checks it), and carries Go, jq, yq, osv-scanner, govulncheck and golangci-lint at the repo's pins but not trufflehog (AGPL); roles with a `Dockerfile` use it until in-cluster builds exist (gap 7). The executor is not an effect (dry-run runs it as local jobs run today). State that the work is split across later parts, and that #317 splits into the API layer and the executor.
