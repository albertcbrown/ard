# Plan for #413

## Implementation

### Steps
1. `internal/pool/stats.go`, `internal/pool/pool.go` (additive): in `Offer`, where `DeniedLimited` and `DeniedBudget` are set, also bump a per-role refusal record (new `p.refused map[refusalKey]refusal`, key = class+role+verdict; value = count and `firstAt`/`lastAt`). Entries expire after a short TTL (about 2 minutes, new const) so they reflect current refusals; purge in `purgeLocked`. The grant decisions, `items` and `setDemandLocked` stay untouched, so no demand is reserved. New `Stats.RefusedBy map[Class][]Refusal` (new type `Refusal{Role string; Reason Verdict; Count int; Since time.Time}`), filled in `Stats()`. Existing `WaitingBy` keeps its meaning (slot demand), which the snapshot reports with reason `slot`.
2. `internal/pool/slot.go` (new accessor if missing): confirm that `Pool` can list held slots for the running-jobs panel. Add `(*Pool) HeldSlots() []HeldInfo` (new; key, candidate, jobID, grantedAt) under `p.mu`, since `Stats` only has counts.
3. `internal/controller/pause.go`, `scheduler.go`, `controller.go`: record data for the snapshot without new calls. In `runner.tick`, after `Pause.Check` write `st` into new `Controller.pauses map[string]PauseState` (loop name -> last result). Also record last tick start, end and error per loop (`ticks map[string]TickInfo`, new). Add `(*Controller) PauseStates() map[string]PauseState` and `(*Controller) Ticks() []TickInfo`, copies under `c.mu`. They never call `PauseGate.Check`, so no GitHub call per frame.
4. New package `internal/snapshot` (stdlib plus the pool, limits, state, budget, config and controller types, imported only through small interfaces defined in the package so fakes are easy):
   - `snapshot.go`: `type Snapshot struct{ TakenAt time.Time; Pool PoolView; Running []RunningJob; Pause []PauseView; Ticks []TickView; Limits LimitsView; Issues []IssueView; Spend SpendView; Events []Event }`. `PoolView` carries Used and Max, plus `Waiting []Waiting{Role, Class, Reason ("slot"|"limited"|"budget"), Count, Oldest}`. `RunningJob` carries Issue, PR, Stage, Role, Model, Elapsed, Timeout and `FinishedCostUSD` (a `*float64`).
   - `Sources` interface set: `PoolSource{Stats(); HeldSlots()}`, `LimitSource{Readings(); Until(family)}`, `StateSource{RunningJobs; JobUsage; IssueUsage; EndedSince or a new open-job listing; SpendSince}`, `ControlSource{PauseStates(); Ticks()}`, `Config func() *config.Resolved`, `Now func() time.Time`.
   - `Taker.Take(ctx) Snapshot`: reads in-memory sources first, then SQLite through `state` only. The running-job cost comes from `JobUsage` (finished steps only, since `step_usage` rows are written when a step ends; the running step contributes nothing). Model and timeout come from the role config. `Limits` holds `Readings()` (utilization normalised to 0..1 via a new helper that handles both 0..1 and 0..100 streams, status, ResetsAt, age = Now − ObservedAt) and `Until(FamilyOf(model))` for opus, sonnet, haiku and "". Issues are the open `ard:` state plus jobs since 00:00 UTC, with the total from `IssueUsage` summed and cached per issue, invalidated by a new `Taker.Invalidate(issue)` / a generation bumped from close-out (cache key: issue + latest job `UpdatedAt`, to avoid touching closeout code). Spend is today's `SpendSince` against `cfg.BudgetUSDPerDay` and the role caps (reuse `budget.Gate.Capped`/`TokenReport` rather than new logic).
   - Take must never use `github.*`: the package must not import `internal/github` (an import test enforces this).
   - `events.go`: `Ring` (fixed size, mutex, `Append`, `Events()` copy) and `NewTee(next slog.Handler, ring *Ring) slog.Handler`, a handler that forwards to `next` unchanged and records time, level, message and a flattened attr string (use `redact` on the text; honour `WithAttrs` and `WithGroup`). Output of `next` must stay byte-identical.
5. `internal/servecmd/serve.go` (wiring only): wrap the serve logger with the tee and construct a `snapshot.Taker` from the pool, limits book, store, budget gate and controller, keeping it available for the `ard serve` UI of #414. It is not rendered yet, so `ard serve` output does not change. A tee on the logger passes everything through to the existing handler.
6. `docs/layout.md`: add `internal/snapshot/` line (and the new pool/controller accessors if layout lists them). Run `make docs-check` if it covers layout.

### Test plan
Command: `make lint test` (`go test ./...`, plus `go vet`, `gofmt -l`).
- `internal/pool/pool_test.go`:
  - `TestRefusalsLimited` and `TestRefusalsBudget`: Offer candidates with the `Limited` or `Budget` hook set; `Stats().RefusedBy` shows role, reason and count, `WaitingBy` is unchanged and decisions equal the earlier verdicts.
  - `TestRefusalsDoNotReserve`: with a refused candidate present, a second loop's grants are identical to a run with the hooks unset for that candidate (the grant decisions are unchanged).
  - Refusals expire after the TTL; `TestHeldSlots` lists adopted and granted slots.
- `internal/controller`: `TestPauseStatesRecorded` (the label pause appears per claiming loop, a non-claiming loop shows none, and a fake `Pauser` counts exactly one `Check` per tick, none from `PauseStates()`), `TestTicksRecorded`.
- `internal/snapshot/snapshot_test.go` (table tests with fakes): pool used/max; waiting reasons `slot`, `limited`, `budget` per role; a running job whose finished steps cost 0.40 plus a running step reports 0.40 (cost of finished steps only), and one with no steps reports nil; elapsed against timeout; every active kill switch (config, label, pause-file, status-unreadable); tick times; readings (normalised utilization, status, resetsAt, age) and a block from `Until`; issues (open `ard:` state; job since 00:00 UTC; a job at 23:59 yesterday excluded) with a total cost and the cache (a second Take makes no second `IssueUsage` call, and Invalidate forces one); spend against the daily caps, and a nil config.
- `TestTakeMakesNoGitHubCall`: use the GitHub fake (`internal/github` fake) wired to the pause gate and status reader; take 3 snapshots and assert zero recorded requests. Plus an import test that `internal/snapshot` has no dependency on `internal/github`.
- `internal/snapshot/events_test.go`: ring overflow keeps the newest N in order, concurrent Append is race-free (`go test -race`), and the tee forwards a record byte-identically to a plain handler with attrs and groups.
- Failure cases: a state read error leaves other fields filled and records the error in `Snapshot.Errors`; a nil config; empty book.

### Risk
Medium. The pool change is small but sits in the grant path; it must only add counters after the existing verdict is set (the dedicated unchanged-grant test covers it). The pool takes `p.mu` for the new reads, so keep them short (concurrency). The controller gains new shared state under `c.mu`. The slog tee wraps the logger for all of serve, so a bug would affect all log output (the byte-identical test covers it); redact text before storing. No migration, no public CLI change, and no protected paths (`.github/`, `.ard/config.yaml`, scanners, triage) are touched.

### Size
L (roughly 900 to 1,300 changed lines including tests, within the block limit). Files: `internal/pool/{pool,stats,slot}.go` and `pool_test.go`; `internal/controller/{controller,scheduler}.go` and a test; new `internal/snapshot/{snapshot,events}.go` with their tests; `internal/servecmd/serve.go`; `docs/layout.md`.
