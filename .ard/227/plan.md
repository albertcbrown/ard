# Plan for #227

## Implementation

### Steps
1. `internal/scanner/marker.go` (new func `SafeTitle(s string) string`): neutralise one-line untrusted text for an issue title or checklist line. In order: replace each control character or newline/tab run with one space (`unicode.IsControl`); replace backtick with `'`; replace `<` with `‹` and `>` with `›` (readable, never live HTML, and `<!--` cannot survive); defuse mentions: replace an `@` that starts a word (at the start or after a non-alphanumeric rune, so `x@y.com` stays readable) followed by a word character with fullwidth `＠` (U+FF20), which is readable and notifies nobody. Also neutralise `[`/`]`-link and `![` image syntax by replacing `](`... only if needed: replace `[` with `(` and `]` with `)` so a title cannot become a link. Collapse repeated spaces, `strings.TrimSpace`. Keep `neutralize` for comment delimiters. Reason: one central rule before any filing or editing.
2. `internal/scanner/marker.go`: call `SafeTitle` in `IssueTitle` (before the `MaxTitleChars` cut, so the cut never splits an escape), in `lineText` (checklist line, keep the "(regression of #N)" suffix added after), and for the `<summary>` in `detailBlock`. This covers create (`pipeline.go:691`), edit and join paths because they all go through these functions. Also make `detailBlock`'s `Files` use the new shared `InlineCode(s string) string` (new, same file): `"`" + strings.ReplaceAll(neutralize(s,false), "`", "'") + "`"`, and use it for the existing inline code at the `Files:` loop.
3. `internal/scanner/marker.go`: body defence for scanner-written free text. In `detailBlock` pass `f.Body` through a new `neutralizeBody` that, outside fenced code blocks and inline code spans, defuses `@name` mentions (same fullwidth rule) and escapes raw `<` that begins an HTML tag or comment (`&lt;`). Leave markdown links and `<details>` that ard itself writes untouched (it only touches the scanner's `Body`). Keep fenced blocks verbatim except that `<!--`/`-->` are already handled by `neutralize`.
4. `internal/roles/scanners/docs/docscan.go:340`: this program is stdlib-only and built standalone, so it cannot import `internal/scanner`. Keep its own `code()` but strengthen it to the same rule: replace backtick with `'`, drop control characters, replace `<`, `>` with `‹`, `›`, and `@` with `＠`. Use it for every path or identifier written into a title or body (`docscan.go:385`, `:426`, and any title built from `pk.name` or a directory name; grep `Title:` in the file and wrap).
5. `internal/roles/scanners/error-codes/errcodes.jq:97`: add `def code: ...` (same rule as step 4, jq `gsub`) next to `safe`, build the title as `(.key | code) + " " + $title`, and use `code` for the paths in `locs` (`:89`); the body already uses a `text` fence, so only escape a fence-closing triple backtick as the cve scanner does.
6. `internal/roles/scanners/cve/merge.jq:128-150`: extend `safetxt` to also map `@` to `＠`, and apply `safetxt` to `$pkg` in the title (`:145`; it currently removes only backticks and newlines, not `<`, `>`, `@`) and to `$m`. The identical copy `.ard/scanners/cve/merge.jq` is a protected path and is not touched (see Risk).
7. `docs/proposal.md` (Scanners section, after "The output schema is strict"): add a paragraph "**Scanner text is untrusted.**" stating: the controller neutralises every title centrally (control characters collapsed, backtick, `<`, `>`, `@` mention and link brackets defused, comment delimiters escaped, length capped) before filing or editing; bodies are markdown, so a scanner must wrap every path or identifier it interpolates in inline code through its own `code()` helper (backtick to `'`, same rule as `detailBlock`'s file list) and must not rely on the controller for body markup; a table test with hostile input guards each starter scanner.
8. Tests (see Test plan).

### Risk
Medium. Titles are part of near-duplicate detection and marker lines, so changing them alters existing issues' text on the next edit; fingerprints do not depend on titles, so dedupe is unaffected. Titles in `cve` lose `<`/`>`/`@` characters. Security-sensitive (it is a hardening of untrusted output) and `neutralizeBody` must not break fenced blocks. Protected path: `.ard/scanners/cve/` is in `merge.protected_paths` and is not edited, so it will differ from `internal/roles/scanners/cve/merge.jq` until a maintainer copies the change. No migration, no concurrency changes.
