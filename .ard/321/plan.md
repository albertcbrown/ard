# Plan for #321

## Implementation

Narrowed by the owner decision on this issue: only the NetworkPolicy-enforced, Admission, HappyPath (including the no-key checks on the agent) and ReadWriteOncePod scenarios. WrongKey, ControllerRestart, the egress/ingress scenarios, the other stub modes and the close-out commit assertion belong to #437 and must not be added here. `deploy/kind-up.sh` does not exist and `deploy/`, `Dockerfile` and `.github/` are protected, so the test creates the cluster itself and the worker must not edit them. Existing code to reuse: `internal/gitx/gittest`, `internal/github/fake`, `internal/executor/kube` (`kube.New`, `kube.Options`), `internal/executor/kube/api`, and the flow in `internal/servecmd/worker_e2e_test.go`. Chart values are in `deploy/charts/ard-serve/values.yaml`. This plan is applied on top of PR #433 where it exists; keep what is there and fill the gaps below.

### Steps
1. `internal/executor/kube/e2e/kind_integration_test.go` (`//go:build integration`, package `e2e`): outer mode. `TestKind*` skip unless `ARD_KIND_E2E=1`; with it set, a missing tool (docker, kind, kubectl, helm) or a CNI that does not enforce NetworkPolicy fails. Keep helpers `needTools`, `run` (deadline plus output capture) and failure dumps (`kubectl describe`, events). Keep the scenarios NetworkPolicyEnforced (a default-deny probe is blocked), Admission (control pod passes, each mutation refused by the VAP or Pod Security) and ReadWriteOncePod (second pod on the claim stays Pending; if it does not, log that storage does not enforce it and do not fail).
2. `internal/executor/kube/e2e/testdata/stub-agent.sh` (new, embedded with `go:embed`, `hello` mode only): writes `hello.txt` and the role file, then prints `env`, `/proc/self/mountinfo`, `ls /proc`, and whether `/var/run/secrets` and `/var/run/ard` exist. Gap fix 1: this file must be in the PR and the embed path must match; confirm with `go vet -tags integration`. Remove references to other modes.
3. Same outer file: pin every image by digest, no tags. The worker has network: resolve the digest of the registry image (replace `registry:2`), the kind node image (`ARD_KIND_NODE_IMAGE` default becomes a `name@sha256:` constant matching the pinned kind release's Kubernetes version, at least 1.30), and any other fixture image (echo or busybox pods, if present) from their registries (for example `docker buildx imagetools inspect` or `crane digest`). Pin the kind version in a constant and in the test's doc comment. Keep the digest next to a comment naming the tag it was resolved from and the date. If kindnet in that kind release does not enforce egress, install Calico with a pinned manifest digest; NetworkPolicyEnforced fails loudly either way.
4. Same outer file, gap fix 3 (containerd `config_path`): check the pinned node image. kind node images from 0.20 on already enable `config_path = "/etc/containerd/certs.d"`, so `certs.d/localhost:5001/hosts.toml` needs no patch. Keep it and add a comment saying so with the kind version checked. Add a preflight in the cluster setup that pulls a tiny digest-pinned image through `localhost:5001` (or `crictl pull` on the node) and fails with a message naming `config_path` if it cannot, so the failure is clear instead of an `ImagePullBackOff` timeout. If the pinned release lacks the default, patch it with `containerdConfigPatches` in the generated kind config instead.
5. `internal/executor/kube/e2e/inner_integration_test.go`: inner mode (`ARD_E2E_INNER=1`), HappyPath only: fixture repo via `gittest`, smart HTTP git server accepting only live tokens from `github/fake`, executor from the chart's env, stub agent in `hello` mode. Assert `Exited` 0, the pulled result contains `hello.txt` and the role file, the agent's stdout has no read token (plain or base64), no `/var/run/ard` or `/var/run/secrets`, the agent container has no Secret volumeMount and `automountServiceAccountToken: false`, and after `Cleanup` the Pod is gone and the token is refused. No close-out commit assertion (#437). The git server may stay read-only (refuses receive-pack).
6. `Makefile`: `kind-e2e` in `.PHONY` and the target `ARD_KIND_E2E=1 go test -tags integration -run TestKind ./internal/executor/kube/e2e/ -timeout 30m`, not part of `test`, with a comment on the required tools. Already present on the PR branch; leave as is.
7. Run `go vet -tags integration ./internal/executor/kube/e2e/`, `go build ./...` and `make lint test`. The gofmt parse error from `internal/roles/testdata` is pre-existing.

### Test plan
- This change is the test; the default build must compile with no tag. Compile checks: `go vet -tags integration ./internal/executor/kube/e2e/`, `make lint test`.
- Cases (human, Docker, about 4 CPU and 8 GiB, `make kind-e2e`): NetworkPolicyEnforced (blocked probe, expected pass), Admission (control pod accepted, each mutation refused), HappyPath (assertions in step 5), ReadWriteOncePod (Pending, or a recorded "not enforced").
- Edge and failure cases: `ARD_KIND_E2E` unset skips; set with a tool missing fails; unenforced NetworkPolicy fails; registry pull misconfiguration fails with the `config_path` message; every wait has a deadline and dumps describe and events.
- Check that no tag-based image reference remains: `grep -nE 'image: *[^@ ]+:[^@ ]+$'` and a scan of image constants in the e2e directory.
- CI workflow under `.github/` is a human task.

### Risk
Medium. Slow, pull-flaky, needs Docker, so it stays out of `make test` and Jenkins; the worker cannot run the cluster scenarios, so a human must run `make kind-e2e` for acceptance. Only a new test directory and the Makefile change, no protected paths. Security-sensitive assertions (token leakage) are the point of the test. Digest pins can go stale and need a human refresh. No public interface, migration or concurrency change.

### Size
M (about 350 to 500 changed lines): `internal/executor/kube/e2e/kind_integration_test.go`, `internal/executor/kube/e2e/inner_integration_test.go`, `internal/executor/kube/e2e/testdata/stub-agent.sh`, `Makefile`.
