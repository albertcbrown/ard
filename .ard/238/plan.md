# Plan for #238

## Implementation

### Steps
1. `internal/agent/agent.go` (new type, new field): add `type Window struct { Type string; Utilization float64; Status string; ResetsAt time.Time }` (Type is the raw window name, e.g. `five_hour`, `seven_day`; `ResetsAt` UTC, zero when absent; utilization as a 0–1 or percent value exactly as the stream reports, documented on the field). Add `Windows []Window` to `Result`, with a comment that it is set whenever the stream carried readings, also with `ErrNoResult`. Reason: the adapter-neutral carrier. Builds as-is.
2. `internal/agent/claude/parse.go`: extend `rateLimitEvent.Info` with `UnifiedWindows` as `json.RawMessage` (raw, so a malformed value never drops the event or counts a skipped line). In the `rate_limit_event` case, after `lim.rateLimitEvent(e)`, call new `readWindows(raw) []agent.Window`, accepting a JSON object keyed by window name (and tolerating an array of objects with a type field). Reuse `resetTime` for reset times. Keep the last reading per window type (later events overwrite earlier), sort by Type for determinism, and set `res.Windows` before the final `switch`, so the `ErrNoResult` return carries them. Ignore unknown fields and negative or NaN values. Do not touch `limitAcc` classification. Read only the CLI-emitted event type, never agent text.
3. `internal/limits/readings.go` (new): `type Reading struct { Window string; Utilization float64; Status string; ResetsAt, ObservedAt time.Time }`. Add `(*Book).Observe(ctx context.Context, ws []agent.Window) error` and `(*Book).Readings() []Reading`. Observe keeps the latest reading per window under `b.mu`, stamped with `b.now()`, and persists under a new meta key `limits.readings` (a separate key from `limits.exhausted`, so the Exhaust path is untouched). On a persist error, leave memory unchanged and return the error. `Open` loads the key; a malformed value logs WARN `limits.corrupt` and starts empty. Readings returns a copy sorted by Window. An empty `ws` is a no-op. Observe logs INFO `limits.reading` (window, utilization, status, resets_at) per window. limits importing agent must not create a cycle (check with `go build`).
4. `internal/servecmd/observe.go` (new): `func observing(next reaper.ParseFunc, book func(context.Context) (*limits.Book, error), auth agent.Auth, log *slog.Logger) reaper.ParseFunc`. Call `next`; if `auth == agent.AuthOAuthToken` and `len(res.Windows) > 0`, call `Observe`. If the book or Observe errors, log WARN `limits.observe_failed` and return the original `(res, err)` unchanged. Record on any returned err, including `ErrNoResult` (the inner closure converts it to nil already, but the wrapper must not depend on that). API-key runs record nothing.
5. `internal/servecmd/reaping.go`: in `reaperParts` and the worker, triage and reviewer wiring where `w.parseFunc()` is called (`reaping.go:115`, `triage.go:33`, `worker.go:49`, `reviewer.go:34`), wrap it once: rename the current body to `rawParseFunc` and make `parseFunc()` return `observing(w.rawParseFunc(), w.limitsBook, w.Model.Auth, w.Log)`. This gives one call-site change, since every caller already uses `parseFunc()`. Confirm the Reaper's test-step path from #234 is not wrapped, since the test step must not be classified or recorded. Check how the worker test step parses.
6. `docs/proposal.md`: update the adapter paragraph in "Executors and the Reaper" (the line beginning "**Agent CLIs plug in through adapters.**"): state that the adapter also reads `rate_limit_info.unifiedWindows` from every `rate_limit_event` into `Result.Windows`, that the controller records the readings for OAuth steps only (including killed steps with no result), logs them as `limits.reading`, and that nothing is gated on them yet (#63).
7. Fixtures: add `internal/agent/claude/testdata/synthetic_windows.jsonl` (clearly named synthetic) holding both windows.

### Test plan
Command: `go test ./...` (and `go vet ./...`).
- `internal/agent/claude/parse_test.go` (or new `windows_test.go`): `TestParseWindows` (fixture with five_hour and seven_day gives two sorted windows); `TestParseWindowsLastWins`; `TestParseWindowsMalformed` (bad `unifiedWindows` gives no windows, no SkippedLines, result intact); `TestParseWindowsNoResult` (stream killed before the result gives `ErrNoResult` and Windows set); `TestParseWindowsMillis` (reset time in ms); the existing limit tests must still pass.
- `internal/limits/readings_test.go`: Observe stores and Readings returns sorted copies; a later Observe overwrites; a reopen from the same Meta restores them; a persist error leaves memory unchanged; corrupt value logs `limits.corrupt`; an empty input is a no-op; Exhaust and Readings do not disturb each other.
- `internal/servecmd/observe_test.go`: OAuth step with windows is recorded and logs `limits.reading`; API-key step is not recorded; Observe error (a failing Meta) still returns the result and a nil error; the inner `ErrNoResult` return still records windows and returns the same error; no windows is a no-op.

### Risk
Low. No gating; Observe errors are swallowed and logged. Public interface change is additive (`agent.Result.Windows`, `agent.Window`). One new meta key, no migration. Not security-sensitive beyond the existing rule that text is read only from CLI-emitted events. Concurrency: `Book.mu` guards Observe, as in Exhaust. No `merge.protected_paths` touched (docs/proposal.md is not protected).
