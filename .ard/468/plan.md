# Plan for #468

## Implementation

Policy calls made here (a maintainer may overrule):
- Commit-author emails seen in `git log` output DO count as PII and are replaced with `<email>`, except the allow-list below. A real person's address is still personal data in a log.
- Allow-listed emails: `noreply@github.com`, `noreply@anthropic.com` (Co-Authored-By trailers) and anything ending `@users.noreply.github.com` (this covers the bot's own `<id>+<login>[bot]@users.noreply.github.com`). Reserved domains such as example.com or `.test` are NOT allow-listed, so a planted test address is redacted.
- Allow-listed IPs: loopback (127.0.0.0/8, `::1`) and the unspecified addresses (`0.0.0.0`, `::`). Private ranges and documentation ranges are redacted.
- Phones: only `+`-prefixed international numbers (7 to 15 digits, spaces, dots, dashes or parentheses allowed) and separated NANP forms (`(555) 123-4567`, `555-123-4567`, `555.123.4567`). Bare digit runs are never phones (timestamps, sizes, hashes).
- Scanner logs that are flagged or fail redaction keep the raw log host-local, as issue-stage does, plus a marker file.

### Steps
1. New `internal/redact/pii.go`. Types: `type PIIOptions struct{ AllowEmails []string; AllowNets []netip.Prefix }`; `type PII struct{...}`; `func NewPII(o PIIOptions) (*PII, error)` (error on a bad allow entry; zero options give the defaults above); `func DefaultPII() *PII`; `func (p *PII) Bytes(b []byte) ([]byte, map[string]int, error)`; unexported `stream(ctx, r io.Reader, w io.Writer) (map[string]int, error)`. Work line by line with a `bufio.Reader`. A line over 1 MiB returns an error (fails closed). Placeholders are fixed: `<email>`, `<phone>`, `<ip>`; counts are keyed `pii:email`, `pii:phone` and `pii:ip`. Email: a hand-written ASCII local@domain matcher (regexp is fine), with the allow-list compared case-insensitively. IPv4: dotted quad with octets 0-255 and a boundary on both sides (previous and next byte not alphanumeric, and not `.` followed by a digit). IPv6: a candidate token of `[0-9A-Fa-f:.]` with at least two colons, validated with `netip.ParseAddr`. Phones as in the policy. Why: one pass, no new dependency, no placeholder can create a match.
2. `internal/redact/redact.go`: add `PII *PII` to `Options` (nil means off). In `Log`, after `secrets.stream` flushes into the temp file and before the first scan, run the PII stream from that temp file into a second temp file in the same directory (0600), swap it in, and merge the counts into `Replaced`. Any error returns the existing zero-result error path and leaves no files. In `Text`, apply `PII.Bytes` after `secrets.Bytes` and before the scan; an error returns `fmt.Errorf("redact text: pii: %w", err)`. Why: the scan sees the final text and both entry points get the pass.
3. `internal/closeout/paths.go` `JobRedactor`: set `o.PII = redact.DefaultPII()` on both branches (builtin only, and Multi with gitleaks). The signature is unchanged. Update the doc comment. Why: the production redactor is the single place close-out gets its policy.
4. Scanner local logs. New `internal/scanner/logredact.go`: `type LogRedactor interface{ Log(ctx context.Context, src, dst string) (redact.LogResult, error) }` and `func redactRunLogs(ctx, log *slog.Logger, mk func(executor.Handle) (LogRedactor, error), h executor.Handle)`. For each non-empty path in `h.LogPath` and `h.StdoutPath`: `Log(path, path+".redacting")`, then `os.Rename` onto the original only when `err == nil && !Flagged`. Otherwise remove the `.redacting` copy, leave the raw log, write a 0600 marker file `<path>.unredacted` (fixed text, no findings) and `log.Warn("scanner.log_unredacted", "job", id, "reason", "flagged"|"error", "rules", ruleIDs)` with no finding text. A failure of `mk` is treated like an error. Add `NewLogRedactor func(executor.Handle) (LogRedactor, error)` to `ExecDeps` (internal/scanner/engine_exec.go:34). In `runJob` (engine_job.go) register a `defer` BEFORE the Cleanup defer, so it runs after Cleanup, once the process has stopped. It is a no-op when the field is nil (tests only). Check that nothing reads the scanner stdout after `finish` (AgentEngine.parse runs inside `finish`). Make the existing 7-day log sweep also remove `*.unredacted` markers (find it with `grep -rn "7 \* 24\|logRetention" internal/janitor internal/reaper`; the reaper deletes failed-job logs at internal/reaper/retention.go:65 and should drop the marker too).

### Risk
Medium. The redactor is security-sensitive and used by every close-out, so a PII false positive can change committed text or block a commit (an error on a very long line). The allow-list and phone and IP rules are the tuning risk. The scanner hook touches the job runner but only after `finish`. No migration, no protected paths from merge.protected_paths (all changes are Go code and docs/proposal.md). `redact.Options` gains an optional field and `JobRedactor` keeps its signature. No concurrency change beyond the existing deferred cleanup order.
