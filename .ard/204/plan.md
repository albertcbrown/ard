4. `internal/scanner/llm.go` (new, pure): `func ParseLLMFingerprint(fp string) (rule, path, symbol string, ok bool)` and `func CheckLLMFingerprints(fs []Finding, exists func(path string) bool) DecodeErrors`, per the issue's grammar: split on `:` into 2 or 3 non-empty fields; rule `^[a-z0-9][a-z0-9-]{0,63}$`; path `^[A-Za-z0-9._/@+-]+$`, `path.Clean(p)==p`, not absolute, no `..` segment, not `.`; symbol `^[A-Za-z_][A-Za-z0-9_./-]{0,127}$`. `CheckLLMFingerprints` also requires the path to be in `f.Files` and `exists(path)`. Errors are `DecodeError{Line: 1-based finding index, Msg: fixed text}` (at most 20, like `maxErrorLines` in `finding.go`); `Msg` never contains the fingerprint or any finding text. The 512-byte cap already lives in `DecodeFindings`.
5. `internal/scanner/neardup.go` (new, pure): `const NearDupThreshold = 0.8`; `type TitledIssue struct{ Number int; Titles []string }`; `type NearDup struct{ Fingerprint string; Issue int }`; `func SimilarTitles(a, b string) bool`; `func SkipNearDuplicates(items []Item, open []TitledIssue) (kept []Item, dups []NearDup)`. Normalise: lowercase, every rune outside `[a-z0-9]` becomes a space, drop one-character tokens and the stop list `a an and for in is of on the to with`; compare as sets; equal non-empty sets match, otherwise both sets need at least 3 tokens and Jaccard >= 0.8; an empty set never matches. Walk items in `lessItem` order (`group.go:34`, most severe first); compare each against every open issue (`Number` > 0) and against earlier kept items of the run (`NearDup.Issue == 0`). A skipped item is not recorded as a row.
